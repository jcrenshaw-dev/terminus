# Phase 3: Owner-only files - Plan 1

## Goal

Install and uninstall never hold `settings.json`'s contents in a file wider than owner-only (#64). Every temporary they create is 0600 from the moment it is opened, in the rewrite, the backup, uninstall's two writes and the stored version file alike, and a `settings.json` Terminus creates is 0600.

## Must be true when done

- Under umask 022, `terminus install` into a Claude config directory that has no `settings.json` leaves one at mode 0600 (AC1).
- Every file `create_temporary` opens is 0600 at the moment it is opened, before any byte is written (AC2).
- After an install under umask 022, an existing 0644 `settings.json` is still 0644, its `settings.json.terminus-backup` is 0600, and the stored version file is 0755 (AC2).
- Uninstall still puts back install's backup as bytes, and the restored `settings.json` keeps the live file's mode, not the backup's 0600.
- `THREAT-MODEL.md` describes the temporary as created 0600 and the backup as 0600 whatever the source's mode, and states, from the installed Claude Code bundle, what mode Claude Code gives `settings.json` when it rewrites it. `CHANGELOG.md` `[Unreleased]` carries #64 under `### Fixed` (AC6, this plan's half).
- Each regression test here fails with its fix reverted and passes with it in place (AC5).

## Context

- Locked: D-02 (the fix is in `create_temporary`, through `terminus_core::owner_only::options()`, and covers every caller), D-03 (an existing `settings.json` keeps its own mode, copied onto the temporary after the write only when it differs), D-04 (the backup is 0600 whatever the source), D-05 (a fresh `settings.json` is 0600 and a settings directory `write_atomically` creates keeps the umask default), D-06 (two-part regression), D-15 (this plan reads the Claude Code bundle), D-16 (the docs change with the code).
- Pattern: `terminus_core::owner_only` carries the mode in the creating syscall. The install-side callers of `create_temporary` are `json_file::write_atomically` (the settings rewrite, and uninstall's `apply` and `overwrite`), `Document::backup`, and `binary::store`, whose `copy_into` sets 0755 before the rename.
- Out of this plan: `Store::open` and `open_read_only` (D-01), the settings directory's mode (D-05), `uninstall.rs` and `binary.rs` (neither changes; both are covered through `create_temporary`), and everything about `data move` (PLAN-2).

### Task 2: Keep an existing settings.json's own mode on a rewrite (D-03)

- **Files:** crates/terminus/src/cmd/install/json_file.rs (fill), crates/terminus/tests/install.rs
- **Action:** In `fill`, copy the target's permissions onto the temporary only when the target exists and its permission bits differ from the temporary's 0600. A 0600 `settings.json` is then never wider than 0600 at any moment, a file the user made 0644 stays 0644, and a target that is absent leaves the new file at 0600 (D-05). Keep the copy best effort, as it is today. Rewrite the comment above it: it currently says a fresh temporary is 0644, and after Task 1 it is 0600. Do not narrow every rewrite to 0600, because that would silently change the mode of a file the user owns and chose (D-03, `audit/claude-security.md:155`). The same `fill` serves uninstall's `apply` and `overwrite`, so uninstall's writes keep the live file's mode by the same rule. In `tests/install.rs`, add a test through Task 1's umask-022 spawn: seed `settings.json` with `SETTINGS`, set it to 0644 explicitly, because the test process's own umask must not decide the seed's mode, then install. Assert the file holds the hook entries and is still exactly 0644.
- **Verify:** `cargo test -p terminus --all-features --test install --test uninstall` passes with the new test. `cargo test -p terminus --all-features --lib cmd::install::json_file::` passes. `grep -n 'set_permissions' crates/terminus/src/cmd/install/json_file.rs` shows `fill`'s call behind a comparison of the two modes. With `fill`'s copy removed altogether, the new test fails reporting 600, which shows it pins the 0644 file's mode. `git diff --stat` lists `json_file.rs` and `tests/install.rs` only.
