# Phase 1: Recall injection framing - Plan 1

## Goal

The `UserPromptSubmit` hook and the `SessionStart` brief stop handing archived tool output to the model as the user's own history (#60). This plan takes tool-result turns out of the prompt hook's injection, in the live hook and in `terminus replay` alike, and records from the installed Claude Code bundle how hook context reaches the model, which plan 2's header is worded on.

## Must be true when done

- A prompt naming a file that an earlier session read with the Read tool gets that Read tool-call turn injected, and nothing from the file's contents (the Read result turn) appears in the hook's output.
- `terminus replay` never counts a tool-result turn as injected, so for the same prompt it credits the same turns the live hook injects.
- Typed prompts and assistant turns are injected exactly as before: every existing prompt, suppression, compaction and decision test passes unchanged.
- THREAT-MODEL.md states, from Claude Code bundle 2.1.302, how a hook's `additionalContext` reaches the model: whether it is wrapped and in what, whom it is attributed to, and whether anything in it is escaped.

## Context

- Locked: D-01 (tool-result turns left out entirely, not labelled, not id-only), D-03 (the dropped turns are `user` turns whose `turns.is_typed` is 0; a null is not dropped), D-04 (after INJ-03's threshold, before the suppressions and the cap, in code `terminus replay` also runs, never a SQL filter inside `search::run`), D-07 (bundle check first), D-11 (the planted-Read test's shape and seam).
- Pattern: `prompt::eligible`, `prompt::within` and `prompt::capped` are the public steps the live arm (`selected`) and `feedback::replay::would_inject` share. The exclusion joins them as one more shared step.
- Out of this plan: the header, the tags, neutralization, the frame's budget, the golden and the docs' delimiter text (all PLAN-2).
