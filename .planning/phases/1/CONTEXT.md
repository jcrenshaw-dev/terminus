# Phase 1: Old store code - Context

Gathered: 2026-10-22
Feeds: /cad-plan 1

## Scope boundary

In: Delete the code #105 lists that exists only for store layouts 1.0.0 can't create: the re-key and twin merge in `recover.rs`, the ten `BRING_FORWARD_COLUMNS` entries, the summary-column drop, `retire_old_boundaries`, and the read-side branches for a store missing those columns or tables. Delete the tests that exist only for that code, and bring the docs and threat model up to date. A 1.0.0 store still opens, ingests and passes `terminus verify`.
Out: How a pass reports recovery's watermark lines (phase 5, #96). Planning tags in comments (phase 2, #106); comment edits here change only wording about the removed code. Any new check for a store damaged from outside Terminus.
Deferred: Removing `DecisionLog::Damaged`, `read::unusable` and `read::damaged` goes to phase 8 (#107). #105 lists `Damaged`, but it reports a 1.0.0 store that lost a table, not an old layout, and phase 8 replaces `unusable` with one `--json` failure path in `main`.
Plan shape: multiple plans, same phase (about ten tasks against `workflow.max_plan_tasks` 8).

## Durable decisions

- D-01 (Recovery): The re-key and twin merge are removed outright, accepting their one remaining effect. 1.0.0 does store absolute keys, for a transcript outside the `projects/<folder>/` shapes, and the re-key rewrote one only if that path later became a symlink into a project folder. After this phase such a transcript stays two sessions. A store with absolute keys from before 1.0.0 is no longer re-keyed; the only one was re-keyed by the first pass in #96. Evidence: `crates/terminus-core/src/ingest/mod.rs:1239-1268`, `docs/design/0003-ingest.md:18`, live store measured 2026-10-22 with 0 keys and 0 `parent_session_key` values in `['/','0')`.

## Decisions

Only the re-key writes `notes` (the drain at `recover.rs:205,207` and `repoint` at `:677`). `recover()` becomes `Store::open`, then `reindex::up_to_date`, then `sweep_watermarks`. Evidence: `crates/terminus-core/src/recover.rs:89-117,119-160,178-791`; `Recovered` is read outside it only through `lines()` and `repaired()` (`ingest/pass.rs:56,283,518`, `ingest/backfill.rs:116,453`, `ingest/mod.rs:125`).
- D-03 (Recovery): Delete `crates/terminus-core/tests/session_keys.rs`, its `[[test]] name = "session_keys"` block in `crates/terminus-core/Cargo.toml:148-151`, and `testkit::plant_old_key`. Evidence: `plant_old_key` is used only by `tests/session_keys.rs:116`; every helper the re-key calls has another caller.
- D-04 (Recovery): Success criterion 1 is checked as a text search, so the `recover.rs` module docs that describe the re-key and the merge are rewritten too. Evidence: `crates/terminus-core/src/recover.rs:8-27,37-40,129-131,176-177`.

- D-06 (Store open and schema): Tests that age a store by dropping a listed column are deleted, or cut to their derived-schema half. The concurrent-open test is rewritten against the missing-table arm, by dropping a table, so the IMMEDIATE-transaction race fix in `bring_forward` stays tested. Evidence: `tests/store_open.rs:471-564,968-1010`, `tests/schema.rs:195-276,487-527,539-595,721`, `tests/reindex.rs:731-860,866-960`, `tests/recall.rs:1644-1690`, `src/inject/brief.rs:684-735`, `tests/feedback.rs:805-815,1326-1450`, `crates/terminus/tests/replay.rs:309-360,466-520`.

- D-08 (Read-side branches): Remove the NULL arm of `config::visible::pre_worktree_column` and its five callers, `DecisionLog::Absent`, the `is_typed` and `recorded` branches in `feedback/replay.rs`, and the same `recorded` branch in `feedback/stats.rs`, which #105 does not list.
