## Durable decisions

- D-01 (layout): `docs/design/` follows Baley's layout: a `README.md` index, a `TEMPLATE.md`, and docs numbered with four digits in DOC-04's order, 0001 overview through 0008 install and release. Numbers are assigned in order and never reused. There is no `c4/`, `prd/` or ADR folder: Baley's C4 views are exported from Structurizr, which needs Java and a downloaded `structurizr.war`, and the roadmap says GitHub renders these docs with no other tool. Evidence: `/code/baley/docs/design/README.md` (Index, "Numbers are four digits", the C4 `run.sh export` section), `/code/baley/docs/design/TEMPLATE.md`, `.planning/ROADMAP.md` (phase 11), `.planning/REQUIREMENTS.md` (DOC-04).
- D-02 (template): `TEMPLATE.md` is a cut-down form of Baley's twelve sections. Each part doc has, in order: purpose and scope; terms; the crate and modules that make the part, with its boundaries to the other parts; records (the tables and files it owns); commands and operations; states and workflows, which carry the diagrams; settings. Baley's roles and actors, instructions served, build status and open questions are left out, because Terminus has no workers, serves no instructions, and every part is already built. Keeping all twelve headings with "Not applicable" under four of them was rejected by the owner. Evidence: `/code/baley/docs/design/TEMPLATE.md` (sections 4, 10, 11, 12), `/code/baley/docs/design/README.md` ("A section that does not apply keeps its heading").
- D-03 (diagrams): Every diagram is hand-written Mermaid in a `mermaid` fence, of one of four types: `flowchart`, `sequenceDiagram`, `stateDiagram-v2` or `erDiagram`. Each has a caption line under it saying what it shows. No diagram carries a `%%{init` line, `style`, `classDef` or a fill, so GitHub themes it for light and dark. Forcing a dark theme was rejected because it breaks GitHub's light theme. RustRover's Markdown preview renders Mermaid and follows its dark theme (the owner, 2026-10-17), so the unset background suits his review. No Mermaid exists in the repo today. Evidence: `/code/baley/docs/design/README.md` (Diagrams table, "leaves its background unset"), `/code/baley/docs/design/0002-system-design.md` (caption form).

Correcting it in place was rejected: 30 files under `crates/` and `fuzz/` cite it by `DESIGN-BRIEF.md:NNN`, and an edit shifts those lines. Its stale claims include `rayon` (§4, §16), a pass that compacts, loops and has a wall-clock bound (§6), tool arguments `offset`, `id` and `ids[]` (§7), a git HEAD delta and mmap in the brief (§8), `recall stats` (§8), `max_size_gb` and `[projects] include_only` (§11), a pointer file named `location` and a free-space guard (§12), and Homebrew, deb and rpm (§13). ## Decisions

- D-05 (citations): Code is named by its full repo-relative path and linked relative to the doc (`../../crates/...`), never by `path:line`, which goes stale on the next edit. `THREAT-MODEL.md`'s `core/...` shorthand is not copied. Evidence: `docs/release.md:7-9,15,32`, `THREAT-MODEL.md:21,26,28,67`.
- D-06 (parts): The subsystems DOC-04 does not name go inside the seven part docs, with no extra docs. Observations, retention, recovery, the decision drain and snapshots are steps of the ingest pass. `verify`, `reindex`, `compact`, `usage`, `export` and `data move` belong to the archive. The terminal `search`, `show` and `sessions` belong to search. Egress redaction belongs to recall, and injection names it. Labels, `replay` and `stats` belong to injection. `doctor` and `uninstall` belong to install, and CI (`test.yml`, `fast.yml`) goes in install and release. Config file resolution goes in the overview. Evidence: `crates/terminus-core/src/ingest/pass.rs:278-330`, `crates/terminus/src/lib.rs` (`USAGE`).
- D-07 (user docs): The design docs link to the user docs for what those already pin down and do not restate it: every option (`docs/commands.md`), every key and default (`docs/configuration.md`), the `--json` fields and exit codes (`docs/json-shapes.md`), install behaviour (`docs/install.md`) and the release checks (`docs/release.md`). Evidence: `docs/commands.md:3,244`, `README.md:89,122,130-143`, `docs/release.md:15,32,44`.
- D-08 (overview): One Rust workspace, two crates. `crates/terminus` is the binary: the `lexopt` CLI, `cmd/*` and `out.rs`. `crates/terminus-core` is the library: store, ingest, index, recall, inject, feedback, observe, retention and config. The one binary has three jobs: the hook (`terminus hook <event>`), the stdio MCP server (`terminus mcp`) and the CLI. The whole-system diagram runs from Claude Code's transcripts (`<root>/projects/**`, from `roots` or `$CLAUDE_CONFIG_DIR`, else `~/.claude`) through the hook, the detached ingest, `terminus.db` and its FTS5 index, to recall over MCP, with injection branching off the hook. The data directory resolves from `TERMINUS_DATA_DIR`, then the `data-location` pointer, then `$XDG_DATA_HOME/terminus` or `~/.local/share/terminus` on Linux and `~/Library/Application Support/terminus` on macOS, and holds `terminus.db` with `-wal` and `-shm`, `LOCK`, `snapshots/`, `injection/` and `decisions/`. `terminus.toml` resolves from `TERMINUS_CONFIG_DIR`, then `$XDG_CONFIG_HOME/terminus`, then `~/.config/terminus`. `ARCHIVE_FORMAT` is 2 and `DERIVED_SCHEMA` is 5. No async runtime and no `rayon`: threads start only in `ingest::backfill`, as `std::thread` workers with one SQLite writer. Evidence: `crates/terminus/src/lib.rs`, `crates/terminus-core/src/lib.rs`, `crates/terminus-core/src/store/open.rs:22,58,61,842,871-956`, `crates/terminus-core/src/ingest/lock.rs:24`, `crates/terminus-core/src/store/snapshot.rs:49`, `crates/terminus-core/src/config.rs:46-63`, `crates/terminus-core/src/ingest/backfill.rs:18,230`.
- D-09 (hooks): `EVENTS` is `SessionStart`, `UserPromptSubmit`, `SessionEnd` and `PostCompact`. The hook spawns `terminus ingest` before it reads stdin, reads at most `MAX_PAYLOAD` (1 MiB) within `DRAIN_DEADLINE` (500 ms), and reads only `session_id`, `transcript_path`, `cwd`, `prompt` and `source`. Injection runs on a thread it never joins, under `INJECT_DEADLINE` (50 ms), and output is at most one `hookSpecificOutput` object, from `SessionStart` and `UserPromptSubmit` only. It exits 0 once the event is known and 2 on an unknown event. `cmd/spawn.rs` detaches by a double fork through the hidden `--reparent` hand-off, std only. The `settings.json` entries are exec-form `{"type":"command","command":"<stable path>","args":["hook","<event>"]}` under `matcher: ""`, written by `cmd/install/targets.rs`. The hook never writes SQLite and never takes `LOCK`. Evidence: `crates/terminus/src/cmd/hook.rs:71-76,86,95,125,232-257`, `crates/terminus/src/cmd/spawn.rs:1-62`, `crates/terminus/src/cmd/install/targets.rs`, `tests/fixtures/hooks/*.json`.
- D-10 (ingest): One pass, in `ingest/pass.rs`, in this order: try-lock `LOCK` (a held lock exits 0); `recover::recover`, which rebuilds derived tables when `DERIVED_SCHEMA` differs and sweeps watermarks; `feedback::drain`, which moves `decisions/*.json` into the table and sweeps old `.decision-*.tmp` and `.inject-*.tmp`; `discover::discover`, over `<uuid>.jsonl` and `subagents/agent-*.jsonl`, never opening an excluded project; a walk with one transaction per file (parse to the last `\n`, capture elision, project through git, lineage, block rows, then turns, `compactions`, `turns_fts`, `entities`, `paths`, then the watermark); `feedback::outcomes`; `observe::observe_new`; `retention::retain`; the `runs` row; and after the lock drops, a rolling snapshot through `VACUUM INTO` when one is due. The pass does not loop, has no wall-clock bound and does not compact. Commands: `terminus ingest`, `terminus ingest <path.jsonl>`, `terminus backfill`. Settings: `roots`, `exclude`, `[capture] mode`, `[retention]`, `[snapshot]`. Evidence: `crates/terminus-core/src/ingest/pass.rs:123-330`, `crates/terminus-core/src/ingest/mod.rs:1-14`, `crates/terminus-core/src/recover.rs`, `crates/terminus-core/src/discover.rs`, `crates/terminus-core/src/derive.rs`, `crates/terminus/src/cmd/ingest.rs`, `crates/terminus/src/cmd/backfill.rs:246`.
- D-11 (archive): Archive tables `sessions`, `blocks` (`session_no`, `block_no`, bytes, hash) and `session_meta`; kept tables `decisions`, `labels`, `observations`; derived tables in `DERIVED_TABLES` order `turns`, `compactions`, `turns_fts`, `entities`, `paths`; operational tables `watermarks`, `runs`, `meta`, whose keys are `archive_format`, `derived_schema` and `last_snapshot_at`. `BLOCK_SIZE` 65536 recorded per session, `ZSTD_LEVEL` 3, BLAKE3 over uncompressed bytes, a session checksum over the block hashes, and an append rewrites at most the last block. Turn ids are `session_no << 24 | turn_seq`. `BRING_FORWARD_COLUMNS` adds columns, and an older archive format is refused, never converted. The prose says "block rows" and never "block-framed blob" or "rebuilds derived tables only", though the module is still named `blob`. Evidence: `crates/terminus-core/src/store/schema.rs:61-509`, `crates/terminus-core/src/blob/mod.rs:23,30`, `crates/terminus-core/src/store/open.rs:10-66`, `crates/terminus-core/src/verify.rs`, `crates/terminus-core/src/reindex.rs`, `.planning/phases/7/UAT.md`.
- D-12 (search): Indexing: `index/text.rs` (text projection, `MAX_BODY_BYTES`), `index/expand.rs` (camel, snake, kebab and path parts added at ingest, plain `unicode61`, no custom tokenizer), `index/entity.rs` (kinds `path`, `command`, `error`, `symbol`, `tool`, capped per turn, error text normalized). Ranking: query tokens quoted and AND-ed up to `MAX_QUERY_TOKENS` 32, ordered by `-bm25` over a pool of `MAX_RESULTS*4`, re-ranked by entity IDF, sidechain turns last on ties; `MAX_RESULTS` 50, `DEFAULT_RESULTS` 20. Scope is a longest-prefix match of the cwd against stored project keys, and excluded projects are never visible. `recall/excerpt.rs` reads only the blocks a turn covers. Evidence: `crates/terminus-core/src/index/mod.rs`, `crates/terminus-core/src/index/entity.rs:27-35,309-315`, `crates/terminus-core/src/recall/query.rs:1-37`, `crates/terminus-core/src/recall/search.rs:21-32,272-320`, `crates/terminus-core/src/recall/scope.rs`, `crates/terminus/src/cmd/search.rs:229-266`.
- D-13 (recall): `cmd/mcp/{mod,rpc,tools}.rs` serve newline-delimited JSON-RPC 2.0 on stdin until EOF, with no port and no lock, opening the store read-only per call. `PROTOCOL_VERSIONS` is `2025-11-25`, `2025-06-18`, `2024-11-05`, `2024-10-07`, default `2025-06-18`; request ids must be integers, and a batch gets `-32600`. Exactly three tools, each `readOnlyHint` true, `destructiveHint` false, `idempotentHint` true, `openWorldHint` false: `recall_search`, `recall_context` and `recall_get`, with the arguments in `tools.rs`. `project: "*"` searches across projects. Failures return an empty result with a `reason`, never a JSON-RPC error. `[privacy] redact_recall` applies through `observe/egress.rs`. Registration is `.mcpServers.terminus` in `~/.claude.json`, through `claude mcp add-json --scope user`. Evidence: `crates/terminus/src/cmd/mcp/mod.rs:1-83`, `crates/terminus/src/cmd/mcp/tools.rs:43-217`, `crates/terminus/src/cmd/mcp/rpc.rs:28,100-108`, `crates/terminus-core/src/observe/egress.rs`, `crates/terminus/src/cmd/install/targets.rs:87`.
- D-14 (#26): The recall doc says what each of `recall_search`, `recall_context` and `recall_get` returns, from the field names they share with `terminus search --json`. The same PR removes the #26 line from README's "Current state" and closes #26 with a `Fixes #26` line. Evidence: `README.md:51`, `crates/terminus/src/cmd/mcp/tools.rs:18-23`, `docs/json-shapes.md`, `.planning/phases/9/CONTEXT.md` (D-08).
- D-15 (injection): Both arms open the store read-only with a 3 ms busy timeout and never write SQLite. The brief holds the last session's typed prompt, its last assistant turn, the branch only, and the session and turn counts, reads no clock, and is capped by `brief_chars` (default 6000, at most `MAX_BRIEF_CHARS` 10000, in characters). The prompt arm fires on an entity match in rank 1-3 (`ENTITY_RANK`) or `CO_OCCURRING` 2, injects at most `MAX_TURNS` 3, applies three suppressions, and is capped by `prompt_chars` (default 4000). After a compaction, `SessionStart` with `source` `compact` sets a flag in `injection/<session>.json`, and the next prompt uses the `COMPACTED_RANKED` pool, filtered to turns before the `compactions` row's offset. Each prompt writes `decisions/*.json`, which the next ingest drains into `decisions`, with `compacted` and `dropped`. Labels are `hit`, `false positive`, `miss` and `wasted budget`. `terminus stats` and `terminus replay` are CLI only. Evidence: `crates/terminus-core/src/inject/mod.rs:1-111`, `crates/terminus-core/src/inject/brief.rs:1-80,167`, `crates/terminus-core/src/inject/prompt.rs:1-101,233`, `crates/terminus-core/src/inject/state.rs:42,72`, `crates/terminus-core/src/inject/decision.rs:50,74`, `crates/terminus-core/src/feedback/label.rs:29-36`, `crates/terminus-core/src/store/schema.rs:180-246`.
