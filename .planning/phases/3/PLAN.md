# Phase 3: One excluded-project rule - Plan

## Goal

The rule that keeps an excluded project out of search, context, get, the brief and the prompt line is written once, on `Scoped`, and every read site calls it, instead of being rebuilt by hand at each site (#80). Nothing any read command shows changes.

## Must be true when done

- Every read command answers exactly as it did before the phase. No existing test and no golden file is edited, and `cargo test --workspace --all-features` passes, `recall_golden` and its `recall-projections.txt` included.
- Three new tests pass, against the code the phase started from and after the change. The brief neither quotes nor counts a session excluded under its pre-worktree key. Get and context refuse a turn excluded only by its pre-worktree key with `NoSuchTurn`. On a store with no `project_pre_worktree` column and an exclusion configured, search and the brief still answer and leave the excluded project out.
- `Scoped` in `recall/scope.rs` holds the one SQL filter, `push_filter`, and the one Rust check, `admits`. Search, the brief and `inject::count` call `push_filter`, and get and context call `admits`. `excluded_projects()` and `excluded_pre_worktree()` are private to `scope.rs`. `push_exclusion` and `ProjectKeys::excluded` are defined nowhere, and `get.rs` and `context.rs` hold no exclusion closure.
- `retention::is_excluded` calls `visible::is_excluded` and holds no check of its own.
- Issue #80 is closed by the merged change (human-verify: needs the merged PR on GitHub).

## Context

- Locked: D-01 `push_filter` writes the scope clause and then both exclusions, at each site where the hand-written block sits now. D-02 `admits(project, pre_worktree)` covers the scope check and both exclusions. D-03 delete `ProjectKeys::excluded()`. D-04 the new tests come first. D-05 the clause text and param order stay. D-06 the empty-list skip stays per list. D-07 alias `m`, and the three rule comments move onto `push_filter`. D-08 `admits` matches exact strings and `Scoped` carries no `Config`. D-09 `visible::is_excluded` takes the two keys. D-10 the list form and the path form both stay. D-11 no other site changes. D-12 the two list accessors become private.
- Out of scope: `crates/terminus/src/cmd/sessions.rs` and `observations.rs`, the `excludes` closure in `visible::projects`, and `covers` and `normalize` in `config.rs`. Those two functions hold the segment-boundary rule from v0.1.0 phase 2 CONTEXT D-09.
- Test conventions to follow: stores built through `ingest::run`, never rows a helper inserted, wherever the path allows it. Configs come from `Config::from_parts`, as in `tests/exclusion.rs` `Tree::config` and `tests/recall.rs` `config`. Worktree sessions are made with a `cwd` of `<repo>/.claude/worktrees/<name>` that nothing creates, as in `tests/exclusion.rs` `a_worktree_session_is_hidden_under_either_of_its_two_keys`.

### Task 2: Write the SQL filter once, on `Scoped`

- **Files:** crates/terminus-core/src/recall/scope.rs (start at `impl Scoped`), crates/terminus-core/src/recall/search.rs (start at `run`, `HEAD` and `push_exclusion`), crates/terminus-core/src/inject/brief.rs (start at `last_session_row`), crates/terminus-core/src/inject/mod.rs (start at `count` and `push_exclusion`)

It takes the SQL being built and its parameter list, the same pair `push_exclusion` and `Filters::push_onto` take, and it appends three clauses in this order (D-01). First the scope clause ` AND m.project = ?`, with the project as an owned `String` param, when `project()` is set. Then the `m.project` exclusion. Then the `m.project_pre_worktree` exclusion. Each exclusion clause is exactly ` AND ({column} IS NULL OR {column} NOT IN (?,…))`, with its null guard and outer parentheses, and with one owned `String` param per value, in list order (D-05). An exclusion is skipped when its own list is empty, list by list (D-06). That per-list skip is what keeps `m.project_pre_worktree` out of the SQL on a store older than that column. Every clause starts with a space, and `push_filter` writes only `AND` clauses, never a `WHERE`. A trailing newline is optional, because every clause any site adds afterwards starts with whitespace (D-05). Choose one form and write it once. The alias is `m`, which every site already gives `session_meta` (D-07). Read the two lists through `excluded_projects()` and `excluded_pre_worktree()`. Task 3 makes those accessors private, and a private accessor nothing calls fails the build with a dead-code warning. The writer of one exclusion clause is either a private helper in `scope.rs` or inline, as you prefer. Nothing outside `scope.rs` may reach it.
  Move onto `push_filter` the three comments that explain the rule (D-07). The first is the null-guard explanation, which today is `inject/mod.rs`'s `push_exclusion` doc and `search.rs`'s call-site comment above the first `push_exclusion` call. Merge the two into one. Keep the ING-08 point that `scope::resolve` only rejects a scope whose own project is excluded, so a visible project's session excluded under its pre-worktree key still has to be filtered here. The second is the "`NOT IN ()` is not SQL" note on `search.rs`'s `push_exclusion`.

In `inject::count`, write ` WHERE 1 = 1` unconditionally and then call `push_filter`, replacing the `match` on `project()` and both calls. ## Notes

- AC3 (c) runs the brief half against the private `render`, not `brief::session_start`. `inject::open` refuses every store that predates the build, and a store with no `project_pre_worktree` column is one of those. So through its public entry the brief answers nothing on such a store, both on main's code and after the change. A test of "the brief still answers" through `session_start` would fail before the refactor started. The unit test checks what D-06 protects, which is that the brief's SQL stays valid on that store.
- AC4 says `git diff main`, but `traders` already holds phase 2's edits to `tests/status.rs`, `tighten.rs` and `uninstall.rs`. Against `main` the diff shows removed lines this phase did not make. So the check runs against the commit Task 1 recorded.
- The `inject::count` `WHERE` (CONTEXT's flagged assumption): `count` writes ` WHERE 1 = 1` and `push_filter` writes only `AND`. If a clause breaks the SQL here, `index_pointer` swallows the error and the brief loses its count line. Task 1 (a) and `recall-projections.txt` both catch that.
