## Decisions

- D-01 (Proving the read): The cause of #75 is taken as settled: in a release build the pass ends before the first `ps` that runs after the hook exits. No push is spent confirming it; the new test's failure message reports whether the pass had already finished (its `runs` row exists), so a later failure confirms or refutes the cause on its own. Measured 2026-10-23 on Linux x86_64: a tree ingest of the test's 10,162,800-byte transcript took 58 to 71 ms in release and 648 to 652 ms in debug, so release leaves about 58 ms over the first poll against about 640 ms in debug. Evidence: `crates/terminus/tests/hook.rs:110-113,173-174,241-259,677-688`, `crates/terminus-core/src/ingest/pass.rs:508-554`, `.github/workflows/test.yml:22-23,139-148`.
- D-02 (Proving the read): The test holds the pass open at the existing testkit fault point (`TERMINUS_FAULT_AT` with `TERMINUS_FAULT_READY`, `fault::stall`, a 30 s `STALL`), which the detached ingest reaches because `spawn::detached` passes the hook's environment on unchanged. A bigger transcript or a faster poll only moves the race. Rejected: a FIFO transcript, and a new testkit hold that waits for a release file. Evidence: `crates/terminus-core/src/ingest/mod.rs:506,758-921,891-905`, `crates/terminus/src/cmd/spawn.rs:64-70`, `crates/terminus/tests/crash.rs:232-270`, `crates/terminus/tests/backfill.rs:463-516`.
- D-03 (Proving the read): The proof is the fault point's ready file plus no `runs` row existing when the read returned. A `ps` lookup stays allowed for a process the hold keeps alive, to find its pid and kill it, because roadmap criterion 1 forbids only polling for a process that may already have exited. Evidence: `.planning/ROADMAP.md` (phase 3 criterion 1), `crates/terminus/tests/hook.rs:366-372,697-715,743-746`, `crates/terminus-core/src/ingest/pass.rs:365-384`.
- D-04 (Proving the read): The stdout read gets a deadline, or the hold is bounded, so a regression can never deadlock the test against its own hold until CI's 15-minute kill. Evidence: `crates/terminus/tests/hook.rs:627-640,668-673`, `crates/terminus-core/src/ingest/mod.rs:891-894`, `.github/workflows/test.yml:165-170,197-203`.
- D-05 (Proving the read): Only that one test changes. `await_process` stays for `the_working_process_leaves_the_group_and_the_parentage_of_the_process_that_spawned_it` and `the_ingest_survives_a_group_kill_and_a_descendant_sweep`, which call it sooner after their spawn. Evidence: `crates/terminus/tests/hook.rs:273-277,791-812`, `.planning/REQUIREMENTS.md` (GATE-01 names one test).
- D-06 (Proving the read): When the pass never reaches the hold within an arrival deadline, the test fails with a message naming `testkit`, as `crash.rs` does, and does not fall back to the old poll. `cargo tree -p terminus -e features -i terminus-core` (2026-10-23) shows the dev-dependency turns on `terminus-core`'s `testkit` for this crate's test build, so a plain `cargo test -p terminus --test hook` gets live fault points. Evidence: `crates/terminus/tests/crash.rs:256-265`, `crates/terminus/Cargo.toml:29-36,56`, `Cargo.toml:2`.
- D-07 (Blocked or stalled): #104 gets a diagnosis, not prevention. Both tests keep their 250 ms and 10 s limits, with no retry, no skip and no change to `test.yml`; only the failure message changes, so it carries evidence for one verdict. If a runner freezes again the merge gate still goes red, with a message that says the runner froze. Rejected: stretching the deadline by the measured stall. Evidence: `.planning/REQUIREMENTS.md` (GATE-02), `.planning/ROADMAP.md` (phase 3 criterion 3), `.github/workflows/test.yml:150-152,182-193`.
- D-08 (Blocked or stalled): "The runner stalled" is judged from two measurements. The test records the largest gap between consecutive polls of a loop that sleeps a fixed short interval, and when the deadline hits it times a spawn of `/usr/bin/true`. The poll gap shows the test process itself was not running; the spawn timing covers a freeze that hits only the disk, which the poll gap alone misreads as "hook blocked". The spawn runs only on a failure. Rejected: the poll gap alone, and a `ps` snapshot of the hook's state at the deadline. Evidence: `crates/terminus/tests/hook.rs:76-83,449-462`, `.github/workflows/test.yml:160-161` (starting `/usr/bin/true` once took up to 150 ms on macOS).
- D-09 (Blocked or stalled): Each message also carries the hook's own evidence. The stdin test reports whether the hook had already written its drain-deadline line ("stopped waiting on a stdin that stayed open for N ms"), which separates "blocked on stdin" from "past stdin but not exited". The stdout test reports whether the hook had exited before EOF arrived, which separates a process the hook started holding stdout from a slow hook. Today the stdout message always blames an inherited handle and the stdin message always blames an unbounded read. Evidence: `crates/terminus/src/cmd/hook.rs:233-245,358-403`, `crates/terminus/src/cmd/spawn.rs:118-127`, `crates/terminus/tests/hook.rs:455-460,627-640,679-683`.
- D-10 (Scope): The two p99 budget tests are outside this phase. CI skips both on every runner, so they never fail the merge gate, and neither #75 nor #104 names them. Evidence: `.github/workflows/test.yml:182-185`, `crates/terminus/tests/hook.rs:379-415,886-925`, `.planning/phases/2/SUMMARY.md` (the local failure at load 12.6, green on re-run).
- D-11 (Verification): Locally the hook tests run with `--all-features` in both debug and `--release`, because only release reproduces #75. Roadmap criterion 2 is proved only by the `macos-15-intel` release job across the milestone pull request's own runs, so it stays open in this phase's UAT until that pull request runs. The phase gets no push of its own. Rejected: one dedicated push after the phase lands. Evidence: `.github/workflows/test.yml:6-9,22-23,139-148,194`.
- D-12 (Verification): Hand edits to `crates/terminus/tests/hook.rs`, and to any testkit code touched, carry no planning tags in comments or messages, and `cargo fmt` is not run over them. Evidence: `crates/terminus-core/tests/planning_tags.rs`, `.planning/phases/1/SUMMARY.md` (rustfmt diffs in `crates/terminus/tests/hook.rs` and `crates/terminus/src/cmd/hook.rs` that predate this cycle).

## Flagged assumptions

- The cause in D-01 rests on timings measured on Linux x86_64. Nothing in the repository measures the cost of `ps -e -ww` or the vCPU count on `macos-15-intel` hosted runners - Likely; if wrong (for example, `ps` on macOS spells this spawn's argv differently), the hold does not fix #75 and AC4 fails on the milestone pull request.
- The two sibling tests that keep `await_process` (D-05) also use `BIG` and keep the same roughly 60 ms release margin - Likely; if wrong, one of them starts missing on a slower runner and comes back as a new issue with #75's message.
- A spawn of `/usr/bin/true` is small and likely cached, so a freeze that stalls only the page-in of the freshly copied `terminus` binary can still slip past D-08 - a guess; if wrong, a message names the hook as blocked for a machine stall.
- How the held ingest's pid is found and the hold ended: a `ps` lookup while the hold keeps it alive, the ready file carrying the pid (a testkit change in `ingest::fault::stall`), or waiting out the 30 s stall - planner's call.
- Only the stdin test polls today, so whether the stdout test gets a poll loop of its own for D-08's gap measurement - planner's call.
