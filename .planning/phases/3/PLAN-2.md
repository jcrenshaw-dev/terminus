# Phase 3: Owner-only files - Plan 2

## Goal

`terminus data move` stops moving the archive into a directory it has not checked (#59). It refuses an existing destination that is a symlink, is owned by another uid, has group or world bits, or cannot be listed, and it checks the destination again after the confirmation, so a directory created while the question waits is refused.

## Must be true when done

- `terminus data move <dest>` exits 1 without asking when `<dest>` is a symlink (with or without a trailing slash), is owned by another uid, has any group or world bit, cannot be listed, or is a file. The store stays where it was and the pointer is not written (AC3).
- A refusal for group or world bits prints the `chmod 700` command for that path (D-10).
- A destination that does not exist, or an empty 0700 directory this uid owns, still moves, and the moved tree is still 0700 directories and 0600 files (AC3; recalled from v0.1.1/phases/3/UAT.md, "data move writes the destination tree owner-only").
- When the destination is created, removed or replaced while `move it? [y/N]` waits, or gains group or world bits or a file, answering `y` is refused and nothing is copied (AC4).
- The pointer records the destination with trailing slashes and `.` parts dropped, the same path the checks ran on (D-08).
- `THREAT-MODEL.md` describes the `data move` destination checks, the unchecked parent directory and the unchecked owner of a store reached through `TERMINUS_DATA_DIR` or an older pointer. `docs/commands.md` and `docs/design/0004-archive-and-block-rows.md` list the new refusals, and `CHANGELOG.md` `[Unreleased]` carries #59 (AC6, this plan's half).
- Each regression test fails with its fix reverted and passes with it in place (AC5).

## Context

- Locked: D-07 (the destination rule), D-08 (normalize before the symlink check), D-09 (only the last part is checked for a symlink, and the parent's owner and mode are not checked), D-10 (refuse a wide destination, never narrow it; `mode & 0o077`), D-11 (the second check after the answer and the lock), D-12 (the regression tests and the uid seam), D-13 (the uid from a probe file, std alone, no `libc`), D-01 (no change to `Store::open`, and its gap is recorded), D-14 (`export`'s check stays as it is), D-16 (docs).
- Pattern: the first check runs in `refuse_impossible_destinations`, called from `run` before anything is printed. `copy_tree` creates the leaf through `terminus_core::owner_only::create_dir_all`, and that call stays. `install::confirm` prints the question as its own line when stdin is not a terminal.
- Out of this plan: `Store::open`, `open_read_only` and `tighten` (D-01), `cmd/export.rs` (D-14), `write_pointer`'s mode, `SECURITY.md` (D-16), and anything about install (PLAN-1).

## Tasks

### Task 1: Normalize the destination before it is checked or recorded (D-08)

- **Files:** crates/terminus/src/cmd/data.rs (absolute; run; tests), crates/terminus/tests/datamove.rs
- **Action:** Make the destination `run` works with an absolute path with trailing slashes and `.` parts dropped, and nothing else rewritten. Keep a `..` part as written, because resolving it as text changes which directory is meant when a parent is a symlink. `absolute` resolves a relative path against the working directory first, and the normalization applies to its result, so a relative `rel/` and an absolute `/x/rel/.` both lose the slash and the dot. Every later use (the printed `to` line, `refuse_impossible_destinations`, `copy_tree`, `write_pointer`) takes this one normalized path, so the check Task 2 adds and the pointer can never disagree about which path was checked. The reason it matters is measured in D-08: `symlink_metadata` on `link/` follows the link, and `PathBuf::join("rel/")` keeps the slash. Add unit tests in a `tests` module in `data.rs` for absolute inputs with a trailing slash, with `.` parts, and with a `..` part kept. In `tests/datamove.rs`, add a test that moves the store with `--yes` to a destination given with a trailing slash that does not exist yet. It asserts that the pointer holds that path without the slash and that `status --json` reports the store there.
- **Verify:** `cargo test -p terminus --all-features --lib cmd::data::` and `cargo test -p terminus --all-features --test datamove` pass with the new tests. With the normalization taken out, the datamove test fails showing the pointer ending in `/`, and restoring it makes the test pass. `git diff --stat` lists `data.rs` and `tests/datamove.rs` only.

### Task 2: Refuse an unchecked existing destination before the question (D-07, D-09, D-10, D-12, D-13)

- **Files:** crates/terminus/src/cmd/data.rs (refuse_impossible_destinations; run; copy_file's doc comment; tests), crates/terminus/tests/datamove.rs
- **Action:** Replace the `read_dir(...).unwrap_or(false)` occupancy test in `refuse_impossible_destinations` with D-07's rule, applied to Task 1's normalized path after the existing same-path and inside-the-source refusals. `symlink_metadata` returning `NotFound` is accepted, and `copy_tree` creates the directory 0700 as it does today. Any other error refuses, ENOTDIR included. An existing destination passes only when it is all of these: not a symlink, a directory, owned by this process's uid, with `mode & 0o077 == 0` (so an inherited setgid bit does not count), listable, and empty. A list failure refuses; it is never read as empty. Each refusal names the path, says why, and says nothing was moved. The group-and-world refusal also carries the command that fixes it, `chmod 700 '<path>'`, in the quoting `doctor` uses for its `chmod u+w` fix. Terminus narrows what it creates and nothing it merely found, so it never runs the chmod itself (D-10). Only the last part of the path is checked for a symlink, so symlinked parents such as macOS `/var/folders` are accepted (D-09). The rule takes the expected uid as a parameter, which is D-12's seam. `run` supplies the uid from a probe file (D-13): create a new file with `terminus_core::owner_only::options()` and `create_new`, read its owner from the open file's metadata through `std::os::unix::fs::MetadataExt`, and remove it. Use `std` alone and add no crate. Learn the uid only when an existing directory has to be compared, so a destination that does not exist costs no probe. Planner's choice, recorded per CONTEXT's flagged assumption: the probe goes in the pointer's directory, the parent of `store::location_pointer_path()`, created the way `write_pointer` creates it. The reason: that is Terminus's own config directory, which the user owns and which this command must be able to write to anyway, so the probe adds no directory the move did not already need. Use a name that carries the pid, and step over a name that is taken rather than opening it. Do not reuse `install::create_temporary`, because its error tells the user to run install again. A probe that cannot be created refuses the move, naming the path and the error. Update `refuse_impossible_destinations`' doc comment ("The three destinations...") and `copy_file`'s reference to it so both say what is now checked. Unit tests in `data.rs` call the rule directly with an empty 0700 directory in a temporary directory. With the directory's real owner as the expected uid, it is accepted. With a different uid, it is refused, and the message names the owner. Two more unit tests show that a regular file at the destination and a path beneath a regular file (ENOTDIR) are refused. Add integration tests to `tests/datamove.rs` on the existing `bench().ingest()` shape. Each refusal test runs `data move <dest> --yes` and asserts exit 1, no `move it?` line on stdout, `terminus.db` still at the source, and no pointer file. The cases are: a symlink to an empty 0700 directory, given both with and without a trailing slash, with the real directory still empty afterwards; an empty directory set to 0777, whose stderr carries `chmod 700`; and an empty directory this uid owns set to 0300. The 0300 test first checks whether this process can list a 0300 directory. If it can, as root can, it prints a line beginning `skipped:` and returns. It sets the directory back to 0700 before it ends, so the temporary directory can be removed. Add one test that this rule still accepts what it should: an empty directory created 0700 moves, the pointer names it, and `terminus.db` is inside it. Without that test, a probe that refused every existing destination would pass all the others.
- **Verify:** `cargo test -p terminus --all-features --lib cmd::data::`, `cargo test -p terminus --all-features --test datamove` and `cargo test -p terminus --all-features --test owner_only` pass with the new tests. With the old `unwrap_or(false)` occupancy test put back in place of the rule's call in `refuse_impossible_destinations`, the symlink, 0777 and 0300 integration tests fail because the store moved. With the uid comparison taken out of the rule, the other-uid unit test fails. Restoring each makes them pass (AC5). `git diff --stat` lists `data.rs` and `tests/datamove.rs` only, so no dependency and no lockfile changed (D-13).

### Task 3: Check the destination again after the confirmation (D-11, D-12)

- **Files:** crates/terminus/src/cmd/data.rs (run), crates/terminus/tests/datamove.rs
- **Action:** In `run`, after `answered` returns yes and `lock::try_acquire` has the lock, and immediately before `copy_tree`, run Task 2's rule again on the same normalized path. Have the first check return what it found at the destination: nothing, or the directory's device and inode number, read through `std::os::unix::fs::MetadataExt` from the same `symlink_metadata` call, so no crate is added. The second check refuses when that changed: something is there that was absent, nothing is there that was present, or a directory with a different device or inode is there. That last case is AC4's "replaced", which D-11's absent-then-present test alone does not catch. The second check still runs the whole rule as well, so a directory that kept its inode but gained group or world bits or a file is refused too. Today `owner_only::create_dir_all` accepts a directory that already exists, which is the exploit #59 describes: the directory is made while the prompt waits. The refusal says the destination changed while the question waited, that nothing was copied, and that the store and the pointer are as they were. It returns before `copy_tree`, so the lock is released and nothing is written at the destination. The uid Task 2 learned may be reused, because a process's effective uid does not change between the two checks. In `tests/datamove.rs`, add D-12's second-check test. Spawn `data move <dest>` without `--yes`, with stdin and stdout piped, and `<dest>` absent. Read stdout line by line until the `move it? [y/N]` line appears. Then create `<dest>` as an empty 0700 directory, a directory the rule alone would accept, so only the absent-then-present refusal can stop it. Write `y` and a newline, close stdin, and assert exit 1, `<dest>` still empty, `terminus.db` still at the source, and no pointer file. Do not give the read loop a fixed sleep: it ends when the question arrives or stdout closes, and a closed stdout without the question fails the test. Add two more tests on the same spawn. In the replacement test, `<dest>` is an empty 0700 directory before the spawn. When the question arrives, rename it to a sibling path and create a new empty 0700 directory at `<dest>`, which only the device-and-inode comparison can refuse. Answer `y` and assert exit 1, both directories still empty, `terminus.db` still at the source, and no pointer file. In the widened test, `<dest>` is an empty 0700 directory before the spawn, and when the question arrives it is set to 0777. It keeps its inode, so only the rule's second run can refuse it. Assert the same four things.
- **Verify:** `cargo test -p terminus --all-features --test datamove` passes with the three new tests, and every existing test passes unchanged. With the second check taken out of `run`, all three fail because the store moved into `<dest>`. With only the device-and-inode comparison taken out, the replacement test fails. With only the rule's second run taken out, the widened test fails. Restoring each makes the tests pass (AC4, AC5). `git diff --stat` lists `data.rs` and `tests/datamove.rs` only.
