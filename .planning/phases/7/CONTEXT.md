## Scope boundary

In: New `owner_only` helpers in terminus-core (an exclusive temporary with a retry under a new name, its symlink form, `replace(path, bytes)` for write-then-rename, an exclusive directory, and a single exclusive owner-only create), with every hand-built exclusive or owner-only create moved onto them: install's temporaries and symlink, the injection state and decision temporaries, the decision target reservation, `data move`'s uid probe, its two exclusive directories and `copy_file`, `store/snapshot.rs` `take` and `cmd/export.rs` `write_owner_only` (#73 and its comment). The hook session-id check kept once. `scripts/sign-release.sh` given its own `valid_version` and manifest check, with the `eval` removed, and a Rust test that fails when the signer's `valid_version`, `digest` or manifest function differs from `install.sh` (#99). The docs and doc comments that state the old behaviour rewritten.

A repair of a config directory that already exists at another mode. A sweep for a stray pointer temporary. Copying the release key into the signer. Running `cargo fmt` over the workspace. The other open issues, #109 to #113 included.
Deferred: None.

## Durable decisions

- D-01 (Signer): `install.sh`'s inline manifest parse (two lines, the `version ` and `sha256 ` prefixes, `valid_version`, 64 lowercase hex digits, and the exact-text digest compare) moves into a named function placed before the script's final brace group, with no change in behaviour. `sign-release.sh` carries a verbatim copy of it in place of its own `grep -x -F "sha256 $actual"` check, so the signer refuses exactly the manifests the installer refuses, and the drift test compares it as text the way it compares `valid_version` and `digest`. John chose this over comparing only the shared `printf 'version %s\nsha256 %s\n'` line, which lets the prefix, hex and version rules drift apart with no test failing. Evidence: `install.sh:209-231` (the parse, inline in the final brace group), `scripts/sign-release.sh:94-101` (its `grep` and digest compare against the tag's version), `crates/terminus/tests/install_script.rs`, #99's 2026-10-22 comment.

## Decisions

- D-02 (Helpers): Every exclusive or owner-only create built by hand moves onto `owner_only`, so criterion 2 holds whichever seven sites a reader counts. The five retry loops: install's `temporary` in `install/mod.rs` (behind `create_temporary` and `binary.rs`'s symlink in `link`), `create_temporary` in `inject/state.rs` and in `inject/decision.rs`, the target reservation in `decision.rs` `write_file`, and the uid probe in `cmd/data.rs` `own_uid`. The two hand-built 0700 directories in `data.rs` (`create_destination` and the `DirBuilder` in `copy_tree`). Also `write_pointer`, the probe's plain `create_dir_all`, `data.rs` `copy_file`, `store/snapshot.rs` `take` and `cmd/export.rs` `write_owner_only`. Evidence: those files, #73 and its 2026-10-22 comment, `.planning/ROADMAP.md` (phase 7 criterion 2).
- D-03 (Helpers): `owner_only.rs` today holds `DIR_MODE`, `FILE_MODE`, `create_dir_all` and `options()`; the new helpers are added beside them. The ingest lock (create, no truncate), `Store::open`'s create of `terminus.db` (where `AlreadyExists` is the normal case) and `data move`'s truncating `LOCK` keep `options()`, because none is an exclusive create and forcing one through would refuse an existing `LOCK` or store. Evidence: `crates/terminus-core/src/owner_only.rs`, `crates/terminus-core/src/ingest/lock.rs`, `crates/terminus-core/src/store/open.rs`, `crates/terminus/src/cmd/data.rs`.
- D-04 (Helpers): The retry helper keeps each site's current names and attempt limits, and has a symlink form. Install tries `{prefix}{pid}` first and then `{prefix}{pid}-{n}`; the state and decision temporaries use `{prefix}{pid}-{n}.tmp`; the probe `.uid-probe-{pid}-{n}`; the decision reservation `{stem}-{pid}-{stamp}-{n}.json`; 64 attempts everywhere except the probe's 100. The names stay because the stale-name test in `tests/install.rs` plants exactly `.terminus-install-{pid}` and `.settings.json.terminus-{pid}`, and the drain's sweep in `feedback/mod.rs` matches the state and decision names. Evidence: `crates/terminus/src/cmd/install/mod.rs`, `crates/terminus/src/cmd/install/binary.rs`, `crates/terminus-core/src/inject/state.rs`, `crates/terminus-core/src/inject/decision.rs`, `crates/terminus/src/cmd/data.rs`, `crates/terminus/tests/install.rs`, `crates/terminus-core/src/feedback/mod.rs`.
- D-05 (Helpers): `replace(path, bytes)` writes through an exclusive 0600 temporary, renames it into place, removes it on failure and does no fsync. It replaces `state.rs` `write_atomically` and the pointer write. An fsync would add a disk flush to every hook state save on the 50 ms hook path. `json_file.rs` `write_atomically` and `binary.rs` `store` use only the temporary helper and keep their own fill: both `sync_all`, `settings.json` keeps the live file's mode, and the binary is chmodded to 0755. Evidence: `crates/terminus-core/src/inject/state.rs`, `crates/terminus/src/cmd/install/json_file.rs`, `crates/terminus/src/cmd/install/binary.rs`.
- D-06 (Helpers): The binary's 0755 stays a chmod at its call site in `binary.rs` and is not a mode option on any `owner_only` helper. If `copy_into` and `copy_through` are merged, the merge stays inside the install module. The versions folder and `~/.local/bin` keep plain `create_dir_all` at the umask default, matching `install.sh`'s `umask 022` and `mkdir -p`. Evidence: `crates/terminus/src/cmd/install/binary.rs`, `crates/terminus/src/cmd/install/json_file.rs`, `install.sh`, the header of `crates/terminus-core/src/owner_only.rs`.
- D-07 (Session id): The session-id check (`MIN_NAME` 8, `MAX_NAME` 64, hex digits and dashes only) exists once in the inject module and returns the checked id; `state.rs` adds `.json` to it and `decision.rs` uses it as the file stem. The comment in `decision.rs` that defends keeping two copies is removed. Evidence: `crates/terminus-core/src/inject/state.rs` (`MIN_NAME` and `MAX_NAME` at 60-61, the check at 247), `crates/terminus-core/src/inject/decision.rs` (65-66, 376, the comment at 60-64), `crates/terminus/tests/owner_only.rs`.
- D-08 (Pointer): The pointer's writer moves into `crates/terminus-core/src/store/open.rs` beside `pointed_at` and `location_pointer_path`, as a public function `data move` calls, built on `owner_only::create_dir_all` and `replace`; its errors reach the CLI through the existing `From<terminus_core::Error> for Failure`. Evidence: `crates/terminus-core/src/store/open.rs`, `crates/terminus/src/cmd/data.rs` (`write_pointer`), `crates/terminus/src/cmd/mod.rs`.
- D-09 (Pointer): Both places that can create the config directory change: `own_uid`'s `create_dir_all`, which runs before the question when the destination already exists, and the pointer writer, which covers the rest. Whichever runs first creates it 0700. A config directory that already exists keeps its mode. Evidence: `crates/terminus/src/cmd/data.rs` (`own_uid`, `write_pointer`), `crates/terminus-core/src/owner_only.rs` (`create_dir_all` leaves an existing leaf alone).
- D-10 (Pointer): The pointer's temporary gets a unique exclusive name from the retry helper in place of the fixed `data-location.tmp`, so a move killed mid-write can leave a stray temporary in the config directory that nothing sweeps. Rejected: a fixed name removed and then created exclusively, the shape `snapshot.rs` uses. Evidence: `crates/terminus/src/cmd/data.rs`, `crates/terminus-core/src/feedback/mod.rs` (the sweep covers only `decisions/` and `injection/`), `THREAT-MODEL.md`.
- D-11 (Pointer): Criterion 1 is proved through the shipped binary under umask 022 in `crates/terminus/tests/owner_only.rs`, with the config directory absent before the move, for an absent destination and for an existing empty one. The bench there creates `config_dir` up front, and `datamove.rs` spawns with the developer's umask, so neither as it stands proves the fix. Evidence: `crates/terminus/tests/owner_only.rs`, `crates/terminus/tests/datamove.rs`.
- D-12 (Signer): `sign-release.sh` gets its own `valid_version` as a verbatim copy of today's `install.sh` function, with the 20-digit u64 bound, not the copy from before 6a75972, which lacked it. The read loop, the `eval` and the two `install.sh: needs ... valid_version` refusals are removed. Evidence: `scripts/sign-release.sh:50-70`, `install.sh:58-77`, `crates/terminus/tests/sign_release.rs` (`a_bad_tag_is_refused`), `git show 6a75972 -- scripts/sign-release.sh`.
- D-13 (Signer): The signer still reads the `release_key=` line from `install.sh` with `grep` and checks it against `release_key='<key>'`; that is a value, not code, so it meets criterion 4. `sign_release_holds_no_copy_of_the_key` stays. Evidence: `scripts/sign-release.sh:39-48`, `crates/terminus/tests/sign_release.rs`, `docs/release.md`, `docs/design/0008-install-and-release.md`.
- D-14 (Signer): The drift test is a Rust integration test in or beside `crates/terminus/tests/sign_release.rs` that reads both scripts as text and cuts each function at its own boundary lines, following `install_sh_holds_the_same_marker` and `install_sh_pins_the_release_key_once`. It compares `valid_version`, `digest` and the D-01 manifest function, and runs under `test.yml`'s `cargo test --workspace` on all four runners, not as a workflow step. Measured 2026-10-23: the two `digest` functions are identical today. Evidence: `crates/terminus/tests/install_script.rs`, `crates/terminus/tests/release_workflows.rs`, `crates/terminus/src/cmd/install/binary.rs`, `.github/workflows/test.yml`.
- D-15 (Signer): A regression test gives the fixture's `install.sh` a `valid_version` with a side effect, such as creating a file, and asserts after a signing run that the file never appears; a text test asserts `sign-release.sh` holds no `eval`. Evidence: `crates/terminus/tests/sign_release.rs` (the fixture), `scripts/sign-release.sh:69`.
- D-16 (Docs and comments): These change with the code: `THREAT-MODEL.md` (the `eval` sentence near line 340, the pointer written with `std::fs::write` through `data-location.tmp` near line 84, and the temporaries table near line 80 if the pointer's temporary needs an entry), `docs/release.md` step 3, `docs/design/0008-install-and-release.md` (lines 5, 22, 110 and 111), the header and the comment at lines 50-51 of `scripts/sign-release.sh`, the site list at `owner_only.rs:8-10`, `decision.rs:60-64`, the doc comments on `install/mod.rs`'s temporaries, `state.rs`'s and `decision.rs`'s `create_temporary`, and `tests/owner_only.rs:373-374`. `docs/design/0004-archive-and-block-rows.md` and `docs/design/0001-overview.md` stay as they are. Evidence: those files.
- D-17 (Docs and comments): New comments and tests cite only #73 and #99, never a requirement id or a decision tag, and comments are rewrapped by hand with no `cargo fmt` over the workspace; `sign_release.rs` and `release_workflows.rs` already carry rustfmt drift. Evidence: `crates/terminus-core/tests/planning_tags.rs`, `.planning/phases/1/SUMMARY.md`.
