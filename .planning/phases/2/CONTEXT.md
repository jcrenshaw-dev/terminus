# Phase 2: Redaction - Context

Gathered: 2026-10-18
Feeds: /cad-plan 2

## Scope boundary

In: With `[privacy] redact_recall` on, a string value under a secret-named JSON key in a `tool_use` input, a `toolUseResult` or an attachment is replaced in every excerpt surface the way `recall_get` already replaces it (PRIV-06, #62). A new rule redacts a bare `sk-` token in prose (PRIV-07, #5). Rule 5's name walk stops slicing inside a multi-byte character, so recall, the hooks and the read commands return normally on a turn like `café=1` (PRIV-08, #61). The egress test checks each planted shape's own marker in the turn that holds it (PRIV-09, #4). That covers the new fixture the phase adds, the regression tests at every process boundary, and the docs that describe what redaction matches.
Out: Changing `text::project` or the FTS body ingest writes (D-01). Changing `recall_get`'s key test, including the `AskUserQuestion` answers it replaces today (D-02). Distinct markers for the header, keyed-JSON and `NAME=` rules (D-04). Curly quotes as value delimiters (D-10). A `catch_unwind` around MCP requests (D-12). Owner-only files (phase 3), session keys (phase 4) and terminal output escaping (phase 5).
Deferred: None.
Plan shape: multiple plans, same phase. `/cad-plan` breaks the four fixes, the fixture, the boundary tests and the docs into plans.

## Durable decisions

- D-01 (Keyed secrets): The keyed-value step runs on the egress side, over the parsed record, before `text::project`, and only when `redact_recall` is on. `text::project` does not change, and neither does the FTS body ingest builds from it. Changing `text::project` would drop secret values from the search index at ingest, which is the ingest-time redaction the project rules out, and it would change what `terminus reindex` rebuilds and break the rule that the knob-off path is byte-identical. Evidence: `crates/terminus-core/src/index/mod.rs:32`; `crates/terminus-core/src/recall/excerpt.rs:211-224`; `crates/terminus-core/src/observe/egress.rs:84-90`; `crates/terminus-core/tests/egress.rs:137-158`; `.planning/PROJECT.md` Key Decisions ("Redact at egress, never at ingest").
- D-02 (Keyed secrets): "Matching `recall_get`" means rule 4's own test, applied at every depth the projection walks. A string value directly under a key whose lowercased name contains any `SECRET_NAMES` fragment is replaced with `REDACTED`. An array, object or number under such a key is not replaced, but secret-named keys nested inside it still are. Measured 2026-10-18 across 2,691 transcripts (771,871 records), walking `tool_use` input, `toolUseResult` and `attachment` to depth 8: 79 records hold such a value. Most are `AskUserQuestion` results, whose `answers` maps are keyed by the question text, so an answer is replaced whenever its question mentions "token", "key" or "api". `recall_get` already replaces those today. Narrowing the test to identifier-shaped keys was considered and left out, because it would change `recall_get` too. Attachments had zero hits. Evidence: `crates/terminus-core/src/observe/egress.rs:535-576` (non-string values skipped at `:570-572`), `:829-833`; `crates/terminus-core/src/index/text.rs:176-195`; `.planning/REQUIREMENTS.md:20` (PRIV-06, "a string value").
- D-03 (Keyed secrets): Key names stay out of the excerpt, and a keyed value is replaced where it stands. A record with no secret-keyed string value projects byte-identically with the knob on and off. The audit's other option, emitting `key: value` lines when the knob is on, is not taken: it would add key names to every knob-on excerpt of a tool turn, move the project-alpha control in the golden and `the_knob_leaves_ordinary_prose_exactly_as_it_was`, and fit less of the turn into the 240-character window. Evidence: `crates/terminus-core/src/index/text.rs:23-26`; `audit/claude-security.md:115`; `crates/terminus-core/tests/redacted_recall.rs:198-207`; `crates/terminus-core/tests/recall_golden.rs:44-52`.
- D-04 (Egress test): For each planted row, the test finds the turn that holds the sentinel in the raw read, then checks that same turn in the redacted read: the sentinel is gone and the row's own marker is present. It does this for the `recall_context` window and for the `recall_get` bodies. The header, keyed-JSON and `NAME=` rules (rules 3, 4 and 5) keep sharing `REDACTED`. Each planted turn holds one shape only one rule can catch, so the turn shows which rule fired. Giving those three rules distinct markers would change what users see (`Authorization: [redacted]`) and about 20 `contains(REDACTED)` assertions. Evidence: `crates/terminus-core/tests/egress.rs:171-349`; `crates/terminus-core/src/config.rs:252-257`; `tests/fixtures/README.md:236-246`; the `contains(REDACTED)` assertions in `crates/terminus/tests/mcp.rs`, `recall_cli.rs` and `brief.rs`, and `crates/terminus-core/tests/inject_brief.rs`, `redacted_recall.rs` and `recall.rs`.

## Decisions

- D-05 (Keyed secrets): One fix in `excerpt::of_record_scrubbed` covers all four excerpt surfaces: `recall_search`, `recall_context`, the prompt hook and the brief. `recall_get` stays on `apply_json_line`, which already redacts keyed values. A fix per surface could miss one; the brief, for example, quotes a last assistant `tool_use` record. Evidence: `crates/terminus-core/src/recall/search.rs:410`; `crates/terminus-core/src/recall/context.rs:257`; `crates/terminus-core/src/inject/prompt.rs:485-491`; `crates/terminus-core/src/inject/brief.rs:575`; `crates/terminus-core/src/recall/get.rs:225-228`.
- D-06 (Keyed secrets): Only the `tool_use` input shape can reach injected text. Phase 1 made the prompt hook drop `is_typed = 0` user turns, attachments carry no entities, and the brief quotes only the last typed prompt and the last assistant record, which never carries `toolUseResult` (phase 1 D-01, D-03, D-08). So the `toolUseResult` and attachment shapes are proven on `recall_search`, `recall_context` and `recall_get`. The injected-text test uses a `tool_use` whose input holds a `PATH_INPUTS` key beside the secret-named key, which makes the turn eligible for any tool name. Evidence: `.planning/phases/1/CONTEXT.md`; `crates/terminus-core/src/inject/prompt.rs:573-594`; `crates/terminus-core/src/index/entity.rs:154-160`; `crates/terminus-core/tests/redacted_recall.rs:281-311`.
- D-07 (`sk-` rule): The rule keys on a generic `sk-` prefix, not a list of provider prefixes, and matches only when 20 or more key characters follow `sk-`. Every real provider key known runs well past that (OpenAI's plain `sk-` and `sk-proj-`, Anthropic's `sk-ant-api03-`, OpenRouter's `sk-or-v1-`, DeepSeek's). The floor skips the archive's placeholders: across the whole corpus, measured 2026-10-18, bare `sk-` 889, `sk-abc` 156, `sk-ant-` 128, `sk-live-` 120, `sk-fake` 118, `sk-svcac` 89, `sk-not-a-quoted-string` 64, `sk-notification` 22, and no OpenSSH `sk-ssh-`/`sk-ecdsa-` key-type names. Test sentinels must be 20 characters or longer after `sk-`. A pinned prefix list would miss OpenAI's plain `sk-` keys and any provider not on it. A floor of 6, the GitHub rule's floor, would redact placeholders such as `sk-notification`. Stripe's `sk_live_` uses an underscore and is outside this rule. Evidence: `crates/terminus-core/src/observe/egress.rs:56-70`, `:142-148`, `:150-164`; `.planning/REQUIREMENTS.md:21` (PRIV-07).
- D-08 (`sk-` rule): The rule has its own marker constant with no whitespace in it. It runs after the named rules 3 to 6, next to the JWT and GitHub rules, so an `Authorization: Bearer sk-...` turn keeps the header rule's marker and D-04's check of that turn still passes. It matches only a whole run of credential bytes (ASCII letters and digits, `-`, `_`) that starts at a run boundary, so `task-notification` never matches. Evidence: `crates/terminus-core/src/observe/egress.rs:118-140`, `:251-264`, `:784-827`; `tests/fixtures/session-envelope.jsonl`; `crates/terminus-core/tests/inject_brief.rs:564-608`.
- D-09 (Multi-byte panic): Rule 5's name walk is the only slice in the rule set that can land inside a character; rules 1 to 4 and 6 to 8 were checked and have none. The fix reads the name run as ASCII only, the way rules 3, 6, 7 and 8 already read names, and starts it after the whole matched character. `café=1` and `Größe=10` come back unchanged, and output on ASCII text does not move. The `redaction` fuzz target already found this crash: the local artifact `fuzz/artifacts/redaction/crash-6d3bb0e0fc5b3fd9ca463f5bcd7278deb90aaa91` is bytes `CA 32 3D 0A`, and artifacts are gitignored. About 26 projections in the 60 most recent transcripts meet the panic condition, all with `é` (approximate, measured 2026-10-18). Evidence: `crates/terminus-core/src/observe/egress.rs:615-619` against `:449-451`, `:705-708`, `:794-799`; `audit/claude-security.md:85-96`; `fuzz/fuzz_targets/redaction.rs`.
- D-10 (Multi-byte panic): Curly quotes stay content, not delimiters. With the knob on, `“token=abc”` becomes `“token=[redacted]`, because the closing U+201D goes with the value run. The phase does not change which characters end a value; making curly quotes delimiters would change rules 5 and 6 together. Evidence: `crates/terminus-core/src/observe/egress.rs:509-525`, `:624-644`.
- D-11 (Multi-byte panic): The panic regression tests run at every process boundary the roadmap names: the MCP tools, both injection hooks, `terminus search` and `terminus show`. The hook tests check that the injection is present and that stderr carries no panic message. The hook already catches the unwind and exits 0 with nothing injected, so an exit-status check alone passes before the fix. Evidence: `crates/terminus/src/cmd/hook.rs:283-306`; `crates/terminus/tests/mcp.rs:1960-2090`; `crates/terminus/tests/recall_cli.rs:1160-1280`; `SECURITY.md:48`.
- D-12 (Multi-byte panic): No `catch_unwind` goes around MCP requests in this phase. The audit suggests it as defence in depth; the rule 5 fix is the root-cause fix. Evidence: `audit/claude-security.md:96`; `crates/terminus/src/cmd/mcp/` (no `catch_unwind`); `crates/terminus/src/cmd/hook.rs:283`.
- D-13 (Fixture): The shapes this phase adds go in a new rooted fixture under its own project key, joining `ROOTED_FIXTURES` with an entry in the fixture README, the way `session-envelope.jsonl` got `project-gamma` and `session-secrets.jsonl` got `project-delta`. That covers the bare `sk-` token in prose, a secret-named key in a `tool_use` input, in a `toolUseResult` and in an attachment, and the multi-byte `NAME=` turns. At planning, John added one PEM private key turn, reusing the fake key shape of `a_pem_private_key_goes_and_a_certificate_stays`, so AC4's sweep reaches rule 1 as well. `session-secrets.jsonl`, the golden and the brief's Cookie tests stay as they are. Adding to `session-secrets.jsonl` was rejected: it shifts golden turn ids, a new last turn changes what the brief quotes and breaks four Cookie-sentinel tests, and a `tool_use` makes the README's "emits no entity" claim false. Writing records inside each test was rejected because the MCP, hook, `search` and `show` tests need a transcript on disk to ingest. Evidence: `crates/terminus-core/src/testkit.rs:44-79`; `tests/fixtures/session-secrets.jsonl`; `tests/fixtures/README.md:255-259`; `crates/terminus-core/tests/inject_brief.rs:933-1042`; `crates/terminus/tests/brief.rs:364`; `crates/terminus-core/tests/goldens/recall-projections.txt:12-30`; `crates/terminus-core/tests/egress.rs:263-280`.
- D-14 (Docs): The docs change in the same change as the code: the #5 line comes out of the README's "Current state", THREAT-MODEL's "What it matches" and "What it misses" are rewritten, the shape list in `docs/configuration.md` and the rule list in the `egress.rs` module doc are updated, and the CHANGELOG gains an `[Unreleased]` entry. `SECURITY.md:16` names no shapes and stays as it is. At planning, John added two more: the README's "Current state" heading comes out with its only line, and `docs/design/0006-recall-through-mcp.md`, which says "eight rules" at `:43` and `:237`, is updated to nine rules and the keyed-value step. Evidence: `README.md:50`; `THREAT-MODEL.md:314-322`; `docs/configuration.md:120`; `crates/terminus-core/src/observe/egress.rs:19-50`; `CHANGELOG.md:10`.

## Acceptance criteria

- [ ] AC1: With `redact_recall` on, a secret string under a secret-named key in a `tool_use` input, a `toolUseResult` and an attachment is absent from that turn's `recall_search` excerpt and `recall_context` text, and each is replaced by `REDACTED` where `recall_get` replaces it. The `tool_use` one is also absent from prompt-hook output. A turn with no secret-keyed string value reads byte-identically with the knob on and off.
- [ ] AC2: With `redact_recall` on, an `sk-` run of 20 or more key characters in prose is replaced by the `sk-` rule's own marker, and `sk-notification` and `task-notification` come back unchanged.
- [ ] AC3: With `redact_recall` on, turns holding `café=1`, `Größe=10` and `“token=abc”` pass through the three MCP tools, the prompt hook, the SessionStart hook, `terminus search` and `terminus show`. Each returns normal output with no panic on stderr, both hooks emit their injection, and `café=1` and `Größe=10` come back unchanged.
- [ ] AC4: For each planted shape, the egress test checks that the secret is gone and that its own rule's marker is present in the same turn, in both the `recall_context` window and the `recall_get` body. Turning off any one rule makes the test fail on that shape's turn.
- [ ] AC5: Each fix's regression test fails on the commit before the fix and passes after it.
- [ ] AC6: The README's "Current state", `THREAT-MODEL.md`, `docs/configuration.md`, the `egress.rs` module doc and the CHANGELOG no longer say a bare `sk-` token is missed, and they describe keyed values being replaced.
- [ ] AC7: The pull request that lands this phase carries `Fixes #62`, `Fixes #5`, `Fixes #61` and `Fixes #4`, and all four close once it merges. (human-verify: needs GitHub, after landing)

## Flagged assumptions

- Every real `sk-` provider key runs past 20 characters after `sk-` - Likely, from general knowledge of provider formats, not checked against provider docs, and the corpus holds no real keys; if wrong: a real key with fewer than 20 characters after `sk-` ships whole.
- GitHub push protection does not flag the test sentinels - Unclear; if wrong: the push is refused and the sentinels need a spelling that is not a real provider format. The planner picks sentinels that are clearly fake.
- Attachment types added upstream later get the same keyed-value treatment because D-02 applies rule 4 at every depth - Likely; the corpus holds no attachment with a secret-named key today, so no real attachment shape has been seen; if wrong: a new attachment type carries a secret under a key shape the walk does not reach.
- Whether the egress test's planted table also spans the new fixture's shapes, or those shapes get their own per-turn test, is the planner's call - Likely either way satisfies AC2 and AC4; if wrong: the `sk-` shape is checked somewhere other than in its own turn.
