# Phase 2: Read-only status and verify - Plan

## Goal

`terminus status` and `terminus verify` open the store through `cmd/read.rs`, the path every other read command uses. A machine with no store gets told so and gets no store, and a store older than the binary gets told so and keeps its schema (#77).

## Must be true when done

- With `TERMINUS_DATA_DIR` naming a directory that does not exist, `terminus status` and `terminus verify` each exit 0, print nothing on stdout, print the no-store reason on stderr, and the directory still does not exist afterwards. With `--json`, each prints one document with `ok: true`, the reason, and every `data` field at zero or null.
- A `terminus.db` that holds no tables at all gets that same answer from `status`, from `verify` and from every other read command, and it still holds no tables afterwards. A `terminus.db` holding tables but no `meta` table still fails as not a terminus store.
- On a format-2 store older than the binary, with `derived_schema` below `DERIVED_SCHEMA` and `decisions.compacted` and `decisions.dropped` absent, both commands exit 0 and print the stale-store line on stderr in both modes. The store's `sqlite_master` and every table's `PRAGMA table_info` are the same after the run as before it.
- On an ordinary store, `status` and `verify` print byte for byte what they printed before this phase, in both modes, `size_bytes` included.
- With a malformed `terminus.toml`, `verify` on a clean store exits 0 and reports no failures.
- `THREAT-MODEL.md`, `docs/commands.md` and `docs/json-shapes.md` no longer say `status` or `verify` creates a store, `CHANGELOG.md`'s Unreleased Fixed section has an entry naming #77, and no code comment still says `status` or `verify` opens through `Store::open`. The regression tests fail against the code this phase started from and pass after it, and `cargo test --workspace --all-features` passes.
- Issue #77 is closed by the merged change (human-verify: needs the merged PR on GitHub).

## Context

- Locked: D-01 both commands open through `cmd/read.rs`, and `Store::open` and `Store::open_read_only` do not change; D-03 `read::open_in` reports a database file that holds no tables at all as no store; D-04 `verify` opens with `Config::default()`; D-05 no store follows `read::empty` and exits 0; D-06 an older store gets the existing stale-store line; D-07 no column fallbacks; D-08 the older-store test shape; D-09 the existing tests that change; D-10 `size_bytes` is unchanged; D-11 the docs and comments to correct.
- Pattern to follow: `cmd/stats.rs` `run`, which matches `read::open()` on `Opened::Ready` and `Opened::Nothing` and hands the empty case to `read::empty`. The no-store test shape is `stats_against_no_store_is_a_reason_and_exits_zero` in `crates/terminus/tests/cli.rs`.
- The read path is the one v0.1.0 phase 3 D-10 and phase 4 D-12 set for search, show, sessions and doctor, and hardin phase 3 D-01 kept `Store::open` unchanged. Those are the recalled decisions this phase extends to `status` and `verify`.
- Out of scope: making the writable open take the ingest lock as an argument (#89, D-02), and any change to the bodies of `Store::open` or `Store::open_read_only`.
