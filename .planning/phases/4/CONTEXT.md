# Phase 4: Steady-state ingest pass - Context

Gathered: 2026-10-20
Feeds: /cad-plan 4

## Scope boundary

In: A measurement of steady-state passes on a copy of the live store, before and after. A pass decides a file is unchanged from its length against the watermark before it reads archive state, and reads each file's rows once at pass start. A grown file's tail is scanned once, not twice. `derive` caches its statements. `roll` answers whether a snapshot is due on the pass's own store (#85). Nothing archived or indexed changes.
Out: Making the writable open take the ingest lock as an argument (#89, filed in phase 2). A `--timing` flag or any other timing feature in the shipped binary. `derive_turn`'s own JSON parse. The slow `observations regenerate` query (#70).
Deferred: None.
Plan shape: multiple plans, same phase.

## Durable decisions

None this phase.

## Decisions

- D-01 (No timing feature): No timing feature is added to the product. The numbers come from the wall clock of the whole `terminus ingest` process, `runs.duration_ms` and `strace -c`, and are recorded in the phase directory. A `--timing` flag would change the shipped `ingest` command line. Evidence: `crates/terminus/src/cmd/ingest.rs:79-96`, `crates/terminus/src/cmd/status.rs:137`, `crates/terminus-core/src/recover.rs:187`; no `benches/`, criterion or tracing in any `Cargo.toml`.
- D-02 (Wall clock): The measurement records the wall clock of the whole process, not only `runs.duration_ms`, which is set before `roll` runs and so cannot show the second store open. Baseline read from the live `runs` table on 2026-10-19: 166 passes that committed at most 2 files took 486 to 14,073 ms, averaging 744 ms, each walking about 2,893 files. Evidence: `crates/terminus-core/src/ingest/pass.rs:136-149`, `:336`, `:343`.
- D-03 (Live store untouched): The live store is never opened writable. Each build runs with `TERMINUS_DATA_DIR` pointing at a copy made with `sqlite3 <live>/terminus.db ".backup '<copy>/terminus.db'"`, the method hardin phase 4 used. A writable open of the live store runs `tighten`, `bring_forward` and `drop_summary_columns`, and a pass from this branch would rebuild every derived table. Evidence: `.planning/_archive-hardin/4/PLAN-2.md:130-138`, `crates/terminus-core/src/store/open.rs:897-905`, `crates/terminus-core/src/ingest/lock.rs:12-14`.
- D-04 (Warm-up): The first pass on the copy is a warm-up and is not measured, because the live store is at `derived_schema` 4 and this branch at 5, so that pass rebuilds 1,147,250 turns. After it, the old and new builds take turns on the same copy; both are `ARCHIVE_FORMAT` 2 and `DERIVED_SCHEMA` 5. Evidence: `crates/terminus-core/src/store/open.rs:22`, `:58`; `crates/terminus-core/src/recover.rs:178-189`; `crates/terminus-core/src/reindex.rs:325-337`.
- D-05 (Live transcripts): The copy reads the live transcripts where they are, never a frozen copy of the tree, and each run's `files_committed` is recorded beside its time. A frozen tree makes every file a "key already held" refusal, about 2,893 per pass. Evidence: `crates/terminus-core/src/ingest/mod.rs:201-202`, `:345-347`, `:994-1004`.
- D-06 (Warm cache): All numbers are taken with a warm page cache, since dropping caches needs root. Warm numbers understate the saving. Evidence: `free -g` on 2026-10-19 (60 GB RAM, 28 GB page cache); `crates/terminus-core/src/store/schema.rs:85-91`.
- D-07 (Issue corrections): The plan works from the code, not from #85's text. A pass walks about 2,893 files, not 4,900; the store holds 5,087 sessions, none evicted or diverged. `ingest_file` does not exist: the function is `ingest_locked` (`ingest/mod.rs:254-266`), and the `append_state` call is at `:1132`. The turn `count(*)` is a covering-index range over one session, 41 ms across all sessions against 5.4 ms for `max(turn_seq)`. An unchanged file costs 7 statements (four in `Existing::read`, two in `append_state`, `stored_holder`) plus an open, fstat, seek and read of the transcript (`mod.rs:401`, `:1334-1376`). Reading every hash took 136 to 152 ms warm and every tail 13 ms, so the block-row reads are about 85 ms of a 490 to 740 ms pass, an estimate by proportion. Evidence: `crates/terminus-core/src/store/archive.rs:297-310`, `crates/terminus-core/src/ingest/pass.rs:385-404`, `crates/terminus-core/src/ingest/backfill.rs:421`; issue #85.
- D-08 (Unchanged-file gate): A file is unchanged when its length matches its watermark. The check runs on the writer thread before `append_state`. Hashes and tail are fetched only when the file is longer than the watermark, the session is flagged diverged, or its stored file is gone. A file that grows after the check is left for the next pass and never appended without its hashes. A gate on "a complete record past the watermark" was rejected, because it needs a connection inside `prepare`, which backfill's workers do not have. Evidence: `crates/terminus-core/src/ingest/backfill.rs:257-261`, `:416-427`; `crates/terminus-core/src/ingest/mod.rs:268-275`, `:391-402`; `crates/terminus-core/tests/compaction.rs:881-927`.
- D-09 (Unchanged-file outcomes): An unchanged file keeps every outcome it gets today: the refusal when another existing file holds the key, the refusal of a session with no `session_meta` row, the 32-byte checksum refusal, the flag for a file shorter than its watermark, and the `transcript_path` update for a moved file. Only the block-row reads and the turn count are skipped. Letting them go silent was rejected, because a damaged session whose file stops growing would read as up to date and `status` and `doctor` would stop naming it. Evidence: `crates/terminus-core/src/ingest/mod.rs:345-347`, `:562-572`, `:1099-1110`, `:1119-1126`, `:1344-1364`; `crates/terminus-core/src/ingest/pass.rs:432-444`; `crates/terminus-core/tests/ingest.rs:512-575`.
- D-10 (Read log): Criterion AC2 is proven by a new log of `blocks` reads that compiles only under `testkit`, built like `discover::opened`, with the hash-list query counted as a read. `Outcome::UpToDate` keeps its shape. `Pass.block_rows_read` is not used, because it counts byte fetches and misses the hash list. Evidence: `crates/terminus-core/src/discover.rs:328-400`; `crates/terminus-core/src/ingest/mod.rs:70-74`, `:508`; `crates/terminus-core/src/store/archive.rs:311-316`; `Cargo.toml:24`.
- D-11 (Pass-start read): Each file's rows are read once at pass start, after recovery and before the walk, in one query joining `sessions`, `session_meta` and `watermarks` (3.8 ms for 5,087 rows). `claim` uses it instead of `stored_holder`. The turn count is not in it: the next `turn_seq` comes from `max(turn_seq)`, read only for files that grew. `count(*)` equals `max(turn_seq)+1` in all 5,083 sessions with turns. Evidence: `crates/terminus-core/src/ingest/pass.rs:262`, `:370-392`; `crates/terminus-core/src/ingest/backfill.rs:313-316`; `crates/terminus-core/src/ingest/mod.rs:213`.
- D-12 (Tests that must hold): The tests that pass unchanged include `crates/terminus-core/tests/backfill.rs` and `crates/terminus/tests/crash.rs` as well as the ingest, recover and divergence tests, because `Existing::read` is shared and backfill must build a store byte-identical to the sequential pass's. No existing test or golden file is edited; lines are only added. Evidence: `crates/terminus-core/src/ingest/backfill.rs:43-45`, `crates/terminus/tests/crash.rs:612`; phase 3 AC4.
- D-13 (One scan): The first scan of a grown file's tail (`ingest/mod.rs:411`) is replaced by a search for the last newline, which is how `scan_from` computes the resume offset. The second scan stays, because turns are derived from it, and `derive_turn` keeps its own parse. Dropping the second scan was rejected, because the stored bytes differ from the file under `lean` and `minimal`. Evidence: `crates/terminus-core/src/parse/mod.rs:61-89`; `crates/terminus-core/src/ingest/mod.rs:411-412`, `:450`, `:505-507`; `crates/terminus-core/src/derive.rs:19-23`; `crates/terminus-core/src/capture.rs:202-205`.
- D-14 (Statement cache): `derive`'s nine statements use `prepare_cached`. rusqlite 0.40.2's cache holds 16 statements by default and evicts the least recently used. The planner counts the distinct statements in the apply and `reindex` loops and sets the cache size explicitly in `Store::open` if the count is above 16. Evidence: `crates/terminus-core/src/derive.rs:83`, `:126-155`, `:216-224`; `~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/rusqlite-0.40.2/src/lib.rs:168`; `crates/terminus-core/src/store/archive.rs` (cached statements at `:86`, `:203`, `:276`, `:297`, `:306`, `:322`, `:355`, `:380`).
- D-15 (Snapshot check): Whether a snapshot is due is answered on the pass's own store inside `locked`, using SQLite's clock, before the lock is released. A writable store is opened after release only when a snapshot is due, and the timestamp is still written after the copy lands. Taking the snapshot before release was rejected, because it holds the lock through a `VACUUM INTO` of a 3 GB store. #89 stays open. Evidence: `crates/terminus-core/src/ingest/pass.rs:154`, `:165-244`; `crates/terminus-core/src/config.rs:398-405`; `crates/terminus-core/src/store/snapshot.rs:76`; phase 2 D-02.

## Acceptance criteria

- [ ] AC1: The phase directory holds a measurement of steady-state passes on a `sqlite3 .backup` copy of the live store, for the build at `57c036e` and the phase's final build. After one discarded warm-up pass, each build has at least 5 timed runs, each with its wall clock, `runs.duration_ms`, `files_committed` and `strace -c` summary.
- [ ] AC2: With the `testkit` read log on, a pass over a session whose transcript is unchanged records no read of that session's `blocks` rows, the hash list included. A grown file, a diverged session and a session whose file is gone still record their reads.
- [ ] AC3: New tests show that an unchanged file still gets, as at `57c036e`, the refusal when another file holds the key, the refusal of a session with no `session_meta` row, the checksum refusal, the flag for a file shorter than its watermark, and the `transcript_path` update for a moved file. Each new test passes at `57c036e` and after the change.
- [ ] AC4: A pass with no snapshot due opens `terminus.db` for writing once, as `strace -e openat` shows on the copy. With a snapshot due, the snapshot is still taken, and `last_snapshot_at` is written only after the copy lands.
- [ ] AC5: `git diff 57c036e` under `crates/*/tests` shows only added lines, and `cargo test --workspace --all-features` passes.
- [ ] AC6: Issue #85 is closed by the merged change. (human-verify: needs the merged PR on GitHub)

## Flagged assumptions

- The distinct statements in one apply or `reindex` loop come to about 14 or 15, inside rusqlite's default cache of 16 - Likely; if wrong: statements are evicted and compiled again every turn and the `prepare_cached` change saves nothing, which D-14's explicit cache size covers.
- Warm-cache numbers are representative of a hook-driven pass - Likely; if wrong: a cold pass reads the walked sessions' share of 1.36 GB of overflow pages from disk, and the measured saving understates the real one.
