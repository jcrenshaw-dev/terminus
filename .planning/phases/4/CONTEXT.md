# Phase 4: Session keys - Context

Gathered: 2026-10-18
Feeds: /cad-plan 4

## Scope boundary

In: A session's key becomes the path below the `projects` folder, at every place that turns a path into a key, so a move or a symlinked `.claude` no longer gives a transcript a second key (ING-13, #57). A transcript that is a symlink is keyed on the file it points at, which covers the sidecar links Claude Code writes on resume. A repair inside recovery merges each pair of twins, re-keys every other session in place and keeps every session that exists only in the archive. `session_key` in `--json` and MCP output carries the new key. That covers the regression tests, the docs that define the key, and ING-13's corrected wording.
Out: A `repair` command (D-08). A bump of the archive format (D-06). A switch for the new key or the repair (D-07). Any change to how discovery resolves the root (D-04). Keying on the `sessionId` or any other record content (D-02). Terminal output escaping (phase 5).
Deferred: None.
Plan shape: multiple plans, same phase. `/cad-plan` breaks it down, likely the key change first, then the repair, then output and docs.

## Durable decisions

- D-01 (Key form): The key is the path below the `projects` folder: `<encoded project dir>/<uuid>.jsonl`, or `<encoded project dir>/<sessionId>/subagents/[workflows/wf_*/]agent-*.jsonl`. It is found from the shape of the path, not by stripping the configured root, so a stored key from an old root that no longer exists still reduces to it. A file under no `projects` folder keeps its canonical absolute path as its key. Measured 2026-10-19 UTC with `find /data/.claude/projects` over 2,733 transcripts in 210 project folders: the path below the project folder is unique in all 2,733 (0 duplicates), while bare agent file names are not (1,407 distinct names across 1,418 sidecar files, 11 pairs). Keeping each session's first absolute-path key and adding a column that maps the path below `projects` to it was considered and rejected: it matches the old ING-13 wording, but leaves two key forms side by side and keeps old keys naming `/home/john` paths. Keying on the configured root as written was rejected because the next root change doubles the archive again. Evidence: `crates/terminus-core/src/ingest/mod.rs:96`, `:977-987`; `crates/terminus-core/src/discover.rs:139-155`; `crates/terminus-core/src/config.rs:544-552`, `:742-744`; `crates/terminus-core/tests/ingest.rs:311-335`.
- D-02 (Key source): The key is computed from the transcript's path alone, before any byte of the file is read, never from record content such as `sessionId` or the project resolved from `cwd`. Measured 2026-10-19 UTC on the live store: the filename stem equals the stored `session_id` for 1,315 of 1,315 top-level `/data` sessions, and for sidecars the session folder equals the record `sessionId` in 1,580 of 1,590, the 10 exceptions being Claude Code's own symlinks (D-03). Keying on `sessionId` plus the agent file name, as #57 suggests, was rejected: it needs a read of every file before the watermark lookup, on worker threads that hold no connection, and lets a forged `sessionId` append one file onto another session's archive. Evidence: `crates/terminus-core/src/ingest/mod.rs:160-166`; `crates/terminus-core/src/ingest/backfill.rs:400-405`; `crates/terminus-core/src/store/schema.rs:64-66`; `crates/terminus-core/src/lineage.rs:85-90`; `THREAT-MODEL.md:240`.
- D-03 (Symlinked transcripts): A transcript that is a symlink takes the key of the file it points at, so it is archived once. On resume, Claude Code puts a symlink in the new session's `subagents/` folder pointing at the earlier session's sidecar. There are 10 such links on disk, each spelled through `/home/john/.claude`, and each of those sidecars is archived twice today (session numbers 2187 and 2562 are both 1,627,975 bytes). The repair merges the existing link pairs by the same rule as the move's pairs (D-10). Leaving them for a separate issue was rejected because criterion 3, each turn returned once, would still fail on a real store. Measured 2026-10-19 UTC with `find -type l` (10 links). Evidence: `crates/terminus-core/src/discover.rs:18-22`, `:236-248`; `crates/terminus-core/src/lineage.rs:95-120`.
- D-10 (Pairing rule): Two sessions count as one transcript when their stored keys reduce to the same new key, and they are merged only when one stream's block hashes are a prefix of the other's. A pair that fails that test is reported, and neither session is deleted. Merging on the key alone was rejected because two diverged files that collide, such as two roots holding different copies, would lose one file's bytes, which is the loss ING-13 forbids. Measured 2026-10-19 UTC across the live store's 2,019 old-key and 2,905 new-key sessions: 2,018 pairs, 2,016 with identical checksums and 2 strict prefixes (17 of 18 and 11 of 12 full block hashes match, and only the old partial tail block differs). None has the old side longer, and none has equal length with different bytes. Evidence: `crates/terminus-core/src/store/archive.rs:231-317`; `crates/terminus-core/src/verify.rs:248-264`; `crates/terminus-core/src/store/schema.rs:72-91`.
- D-11 (Survivor): The twin with the lower `session_no`, the old-key one (0-2018 against 2019-4923), is kept and re-keyed. It takes any stream bytes and non-null `session_meta` columns the other twin holds: on the live store, two newer twins hold 4,637 and 278,468 more bytes, and two others are the only ones with `continues_from`. Its watermark moves to the new key in the same transaction. References into the newer twin, in `labels.turn_id` and the decisions' injected and candidate turn ids, are rewritten to the same `turn_seq` under the survivor, which is exact because the streams share their prefix. The newer twin is then deleted whole, in the order `retention::apply::delete_one` uses. Measured 2026-10-19 UTC with `json_each`: 29 injected, 211 candidate turn ids and 26 labels point into old twins, and 52 decisions carry a watermark of 2018 or less; 9 injected, 91 candidates and 7 labels point into new twins. Leaving the new-twin references dangling was rejected because 7 labels and 100 turn ids would point at nothing. Keeping the new twin was rejected because the 52 pre-move decisions' replay bounds would stay wrong and replay would report every label they stored as lost. Evidence: `crates/terminus-core/src/store/schema.rs:28-48`, `:187-191`, `:231-236`; `crates/terminus-core/src/feedback/replay.rs:10-14`, `:307`; `crates/terminus-core/src/retention/apply.rs:171-200`; `crates/terminus-core/src/recover.rs:151-170`; `crates/terminus-core/src/ingest/mod.rs:274-316`.
- D-13 (Output): `session_key` in `--json` output (search hits, `sessions`, `verify`, `observations`, the `export` manifest) and in the `recall_search` and `recall_get` MCP results carries the new key. The absolute path stays in `session_meta.transcript_path`, which ingest already overwrites on every pass. No command takes `session_key` as input. A script that opens `session_key` as a file breaks, and `CHANGELOG.md` says so. Keeping the absolute path under `session_key` and adding a new field for the stable key was rejected, because a field named `session_key` that is not the key misleads every later reader. Evidence: `docs/json-shapes.md:77`, `:155`, `:201`, `:304`, `:530`; `crates/terminus/src/cmd/mcp/tools.rs:403`, `:559`; `crates/terminus/src/cmd/show.rs:249`; `crates/terminus/src/cmd/sessions.rs:219`; `crates/terminus/src/cmd/export.rs:301`; `crates/terminus-core/src/ingest/mod.rs:1255`; `crates/terminus-core/src/store/schema.rs:96`.

## Decisions

- D-04 (Discovery): Discovery keeps resolving the root once (D-17) and keeps yielding absolute paths. Only the key made from those paths changes. Evidence: `crates/terminus-core/src/discover.rs:18-22`, `:72-79`, `:143`; `crates/terminus-core/tests/discover.rs:135-157`.
- D-05 (Key sites): Every place that turns a path into a key changes in one change: `path_key` and the `canonicalize` in `run_with` (`ingest/mod.rs:96`, `:977`), `flag_divergence` (`ingest/mod.rs:603`), backfill's `read_existing` (`ingest/backfill.rs:401`), `lineage::sidecar_parent`, which feeds `parent_session_key` (`ingest/mod.rs:365`), `inject::prompt::current_session` (`inject/prompt.rs:751`), and `watermarks.transcript_path`, which holds the session key (`ingest/mod.rs:620`). If `current_session` keeps the old form, the compaction lookup finds no boundary and the live session's own turns are injected back into it. Evidence: `crates/terminus-core/src/lineage.rs:91-94`; `crates/terminus-core/src/inject/prompt.rs:408-411`, `:733-754`; `crates/terminus-core/src/inject/compaction.rs:61-98`.
- D-06 (Format): `ARCHIVE_FORMAT` stays 2, and existing 0.1.x stores are re-keyed and repaired in place. A bump would make every 0.1.x store, including the live 3.0 GB one, refuse to open with `ArchiveFormatTooOld`. Evidence: `crates/terminus-core/src/store/open.rs:10-22`, `:806-815`; `CHANGELOG.md:175`, `:194`.
- D-07 (No switch): The new key and the repair apply unconditionally. The old behavior is the defect #57 describes, so no existing user depends on it, and a switch that defaults off would leave every doubled store doubled. Evidence: `crates/terminus-core/src/recover.rs:1-6`.
- D-08 (Where the repair runs): The repair runs in the binary inside recovery, at the top of every ingest run, under the ingest lock, in one transaction. There is no `repair` command. The `recover.rs` module comment saying `sessions` and `session_meta` "are not touched" is rewritten in the same change. Evidence: `crates/terminus-core/src/recover.rs:1-22`, `:108-115`; `crates/terminus-core/src/ingest/pass.rs:259-262`; `.planning/PROJECT.md` Out of Scope.
- D-09 (Repair order): The repair runs after `Store::open` brings the columns forward and before `reindex::open_up_to_date` rebuilds derived tables, so the twins about to be deleted are never rebuilt. The live store reads `derived_schema 4` against `DERIVED_SCHEMA = 5`, so its first pass after upgrade rebuilds everything, and 506,825 of its 1,118,294 turns are old-key (measured 2026-10-19 UTC). Evidence: `crates/terminus-core/src/recover.rs:108-115`; `crates/terminus-core/src/store/open.rs:58`.
- D-12 (Unpaired sessions): A session with no twin keeps its bytes untouched and is only re-keyed, whether or not its file still exists. That covers the one old-key orphan (`-code-cadence/388a000f-...jsonl`: 857,565 bytes, 110 turns, file gone) and 175 new-key sessions whose files are also gone. Measured 2026-10-19 UTC by checking each of the 4,924 keys on disk; none of the 175 has a twin. Evidence: `.planning/REQUIREMENTS.md:35`; `crates/terminus-core/src/recover.rs:20`.
- D-14 (Regression tests): Two regression tests run on real temp SQLite. The first runs a pass over a temp root, renames the root, leaves a symlink at the old path, and checks a second pass leaves the session count unchanged. The second plants a doubled store holding an identical twin pair, a prefix twin pair, a link pair, an archive-only orphan and a pair whose block hashes are not a prefix of each other, and checks that one pass leaves one session per transcript, keeps the prefix pair's longer stream, leaves the orphan's bytes unchanged, reports the non-prefix pair and keeps both its sessions, and that `terminus verify` passes. The key expectation in `tests/ingest.rs:311-335` changes. Evidence: `crates/terminus-core/tests/ingest.rs:311-335`; `crates/terminus-core/tests/discover.rs:135-157`; `crates/terminus-core/src/testkit.rs:120-145`, `:325-337`; `.planning/phases/3/CONTEXT.md` (D-06, D-12).
- D-15 (Docs): The docs that define the key change in the same change as the code: `THREAT-MODEL.md:12`, `:21` and `:240` (240 is a security claim), `docs/design/0003-ingest.md:18-19`, `docs/design/0004-archive-and-block-rows.md:15`, `:66`, `:96`, `:201`, `:417`, `docs/json-shapes.md`, the module comments in `discover.rs`, `verify.rs` and `recover.rs`, and a `CHANGELOG.md` `[Unreleased]` entry under `### Fixed` that also records the `session_key` output change (D-13). Evidence: `crates/terminus-core/src/verify.rs:38-45`; `.planning/phases/3/CONTEXT.md` (D-16).

## Acceptance criteria

- [ ] AC1: After a pass over a transcript tree, renaming the tree, leaving a symlink at the old path and running ingest again, `terminus status` shows the same session count as before the move.
- [ ] AC2: A sidecar that is a symlink to another session's sidecar under `projects` is archived once, under the key of the file it points at.
- [ ] AC3: On a planted store that holds an identical twin pair, a prefix twin pair, a link pair and an archive-only orphan, one ingest pass leaves one session per transcript. The kept session in the prefix pair holds the longer stream, the orphan's bytes are unchanged, and `terminus verify` passes. A planted pair whose block hashes are not a prefix of each other is reported, and both of its sessions are still there.
- [ ] AC4: On a copy of the live store, after one ingest pass, `recall_search` returns each turn once, `terminus status` counts each session once, the `-code-cadence/388a000f` orphan is still archived, and no label or decision turn id points at a turn that doesn't exist.
- [ ] AC5: `session_key` in `--json` output and in MCP results is the path below `projects`. `THREAT-MODEL.md`, `docs/json-shapes.md` and design docs 0003 and 0004 describe the new key, and `CHANGELOG.md` `[Unreleased]` carries #57 under `### Fixed`.
- [ ] AC6: Each regression test fails on the commit before the fix and passes after it.
- [ ] AC7: The pull request that lands this phase carries `Fixes #57`, and #57 closes once it merges. (human-verify: needs GitHub, after landing)

## Flagged assumptions

- Re-keying `sessions.session_key` works inside one transaction while foreign keys are enforced and declared without `ON UPDATE CASCADE` (`schema.rs:94`, `:258`, `:275`, `:322`), through `PRAGMA defer_foreign_keys` or a copy-then-delete order on the bundled build - Unclear, the planner's to test; if wrong: the repair's transaction fails on its first update, and every ingest run stops at recovery.
- Two configured roots holding the same path below `projects` share one key under D-01 - Likely rare; if wrong: the second root's file shares the first one's watermark and is refused as rewritten on every pass. Whether discovery handles it is the planner's call.
- The `transcript_path` in a hook payload always contains a `projects` folder, in whichever spelling Claude Code sends after a move - Likely, both spellings reduce to the same key under D-01; if wrong: `current_session` falls back to the absolute path, finds no session, and the live session's suppression and compaction recall stop working.
- Claude Code's sidecar links always point at a file under a `projects` folder - Likely, 10 of 10 on disk do; if wrong: such a link is keyed on its target's absolute path and is still archived once.
- The 11th pair of matching agent file names is a real copy with its own `sessionId`, so its two sessions are not duplicates and stay - Likely, measured 2026-10-19 UTC; if wrong: that sidecar's turns still show twice and AC4 fails on it.
