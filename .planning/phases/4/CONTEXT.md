## Durable decisions

- D-01 (Unindexable words): Which query words are dropped is decided by a plain Rust table of the code points the bundled SQLite's `unicode61` tokenizer cannot start a token on, so `Query::parse` needs no connection and stays infallible. A test sweeps every code point `char::is_alphanumeric` accepts through the linked bundled SQLite and fails on any disagreement with the table, so a rusqlite bump that moves SQLite's Unicode tables fails the suite rather than bringing back zero-hit searches. Measured 2026-10-23 on rusqlite 0.40.2 bundled (SQLite 3.53.2): of 149,106 Rust-alphanumeric code points, 1,061 in 167 ranges produce no token, none numeric, 131 cased (U+0345, circled Latin letters such as U+24B6). Rejected: probing the tokenizer at search time through a temp FTS5 table and `fts5vocab`, which cannot live in `Query::parse` and costs every search, the prompt hook included, a DDL statement; and adding a Unicode general-category crate, which needs vetting under `deny.toml`. Evidence: `crates/terminus-core/src/recall/query.rs`, `crates/terminus/src/cmd/search.rs` (the query is parsed before `read::open`), `crates/terminus-core/src/inject/prompt.rs` (`candidates` decides whether the store is opened), `fuzz/fuzz_targets/search_query.rs` (calls `Query::parse` with no store), `libsqlite3-sys-0.38.2/sqlite3/sqlite3.c` (`fts5UnicodeTokenize` starts a token only on `L* N* Co`), `Cargo.lock`.

## Decisions

- D-02 (Unindexable words): A word is dropped only when the tokenizer would make no token from any of its characters. A word with at least one indexable character is kept whole and quoted as typed, because FTS5 splits it inside the quoted phrase itself. Ordinary Hebrew, Arabic and Devanagari words carry vowel points and marks from the unindexable set (U+05B0 to U+05BD, U+064B to U+065F) inside them and must keep their search terms. Measured against one row `'foo bar'`: `"foo"` gives 1 hit, `"foo" AND "ͅ"` 0, `"fooͅbar"` 1. Evidence: `crates/terminus-core/src/store/schema.rs` (`turns_fts` sets no tokenize option, so `unicode61` applies), `crates/terminus-core/src/recall/query.rs` (`match_expression` quotes each word).
- D-03 (Unindexable words): The drop is made in `Query::parse`, before the case-folded dedup and before the `MAX_QUERY_TOKENS` cap, so `tokens()`, `is_empty()`, `truncated()`, `match_expression()` and `matches_entity()` all see the same list. A query made only of such words takes the existing path to `Reason::NothingSearchable`. Evidence: `crates/terminus-core/src/recall/query.rs` (`parse`, `is_empty`, `truncated`), `crates/terminus-core/src/recall/search.rs` (`run`, `weight_by_entities`), `crates/terminus-core/src/inject/prompt.rs` (`candidates`), `crates/terminus/src/cmd/search.rs` (`truncated`), `crates/terminus-core/src/recall/excerpt.rs` (`first_token`).
- D-04 (Dates): terminus-core gets one public date check, and all four callers of `cmd::time_bound` use it: CLI `search`, CLI `sessions`, CLI `observations regenerate` and MCP `optional_time`. `cmd::time_bound` is then deleted. Evidence: `crates/terminus/src/cmd/mod.rs` (`time_bound`), `crates/terminus/src/cmd/search.rs`, `crates/terminus/src/cmd/sessions.rs`, `crates/terminus/src/cmd/observations.rs` (`regenerate_args`), `crates/terminus/src/cmd/mcp/tools.rs` (`optional_time`), `crates/terminus-core/src/observe/mod.rs` (`regenerate` does not check its `since`).
- D-05 (Dates): Each front end still checks a date when it reads its arguments, before the store opens. The CLI maps the core error to misuse, exit 2, naming `--since` or `--until`; MCP maps it to `Refused::caller` (`isError: true`), naming `since` or `until`. The `Err(Error::InvalidTimeFilter { .. })` arms in `cmd/search.rs` and `cmd/mcp/tools.rs` can no longer be reached and are removed, as the 2026-10-22 simplify review's comment on #24 asks. Evidence: `crates/terminus/src/cmd/search.rs` (`Opened::Nothing` exits 0 before `search::run`), `crates/terminus/src/cmd/mcp/tools.rs` (`run_search` calls `optional_time` before `reader()`), `crates/terminus/tests/observations.rs` (`a_malformed_since_is_misuse_and_rebuilds_nothing`), `docs/json-shapes.md`.
- D-06 (Dates): `recall::search::run` checks its date bounds before it calls `scope::resolve`, so a library caller passing a bad date from a directory no project covers gets `InvalidTimeFilter`, not `Ok` with `UnknownProject`. Evidence: `crates/terminus-core/src/recall/search.rs` (`run`, `Filters::push_onto`), `crates/terminus/tests/recall_cli.rs` (`a_bad_command_line_is_misuse_and_not_an_empty_result` uses `--project *` to step around the order), `.planning/ROADMAP.md` (phase 4 criterion 3).
- D-07 (Dates): The check validates the clock fields of the full form as well as the calendar: hour 00 to 23, minute and second 00 to 59, month 01 to 12, and a day within the month's Gregorian length. It keeps `Error::InvalidTimeFilter { field, value }`, and the message stops saying the shape is wrong when only the calendar or the clock is. Evidence: `crates/terminus-core/src/recall/search.rs` (`bound`), `crates/terminus-core/src/error.rs` (`InvalidTimeFilter` and its message), `crates/terminus-core/tests/recall.rs` (`a_malformed_time_is_a_caller_error`).
- D-08 (Lists): Every list is passed as one JSON array parameter read through `json_each`, serialized with `serde_json`, which core already depends on, and no `repeat_n("?")` builder is left: the paths filter and the re-rank's turn ids in `recall/search.rs`, `rows_for` in `recall/get.rs`, `coordinates` in `recall/excerpt.rs`, and the two `NOT IN` exclusion lists in `Scoped::push_filter` in `recall/scope.rs`. The model is `feedback/label.rs`; `inject/prompt.rs`, which #108 names, has no `json_each`. `push_filter` keeps its null guard, because `NULL NOT IN (...)` is never true and sessions with no project would drop out of search, the resume brief's last session and the counts. Its callers are `recall/search.rs` (`run`), `inject/brief.rs` (`last_session_row`) and `inject/mod.rs` (`count`). Measured 2026-10-23: `IN` with 40,000 placeholders fails at prepare with "too many SQL variables", and `json_each` over 300,000 elements returns every row; the bundled build defaults `SQLITE_MAX_VARIABLE_NUMBER` to 32766 and enables JSON1. Evidence: those files, `crates/terminus-core/Cargo.toml` (`serde_json`), `libsqlite3-sys-0.38.2/build.rs`.
- D-09 (Lists): `MAX_PATHS` is removed, with the descriptor's `maxItems`, the "only the first N of M paths" reason, the cap assertion in `a_path_filter_longer_than_the_cap_is_bounded_and_said_so`, and its mentions in `docs/commands.md` and `docs/design/0006-recall-through-mcp.md`. Its doc gives the placeholder-per-path failure as its reason, and the output is already capped by `MAX_HITS`. Evidence: `crates/terminus/src/cmd/mcp/tools.rs` (`MAX_PATHS`, `descriptors`, `run_search`), `crates/terminus/tests/mcp.rs`, `docs/commands.md`, `docs/design/0006-recall-through-mcp.md`.
- D-10 (Lists): `MAX_IDS` stays at 25, because each id can cost a whole decompressed session. Its doc, `run_get`'s doc and the doc of `a_list_longer_than_the_cap_is_truncated_and_said_so` stop citing one SQL placeholder per id. `terminus show` stays uncapped. Evidence: `crates/terminus/src/cmd/mcp/tools.rs` (`MAX_IDS`, `run_get`), `crates/terminus/tests/mcp.rs`, `docs/design/0006-recall-through-mcp.md`.
- D-11 (Proof): Paths past the variable limit are proved by a core test that sends at least 32,767 paths through `search::run`, and by the existing 40,000-path MCP test over stdin, rewritten to expect hits with no error and no cap notice. No CLI test sends that many `--path` arguments: about 1 MB of argv, against an `ARG_MAX` on the macOS runners nobody has checked, could fail the merge gate with E2BIG for a reason that has nothing to do with SQLite. Rejected: a CLI test with 32,767 or more `--path=x` arguments. Evidence: `.github/workflows/test.yml` (matrix), `crates/terminus/tests/mcp.rs`, `crates/terminus/tests/recall_cli.rs`, `getconf ARG_MAX` = 2,097,152 on this Linux machine (2026-10-23).
- D-12 (Docs and tests): Tests and docs that state the old behaviour are rewritten, not only extended: the comment in `mcp.rs`'s `a_malformed_call_is_an_empty_result_with_a_reason_and_never_a_throw` that calls `2026-13-99` deliberately not a caller error, the `--project *` workaround comment in `recall_cli.rs`, the `time_bound` doc that goes with the function, the "Time bounds" paragraph in `docs/commands.md`, "in neither time form" in `docs/json-shapes.md`, and in `docs/design/0005-search.md` the claim that `unicode61` splits on every character that is not a letter or a digit and the query flowchart that resolves scope before the filters. Evidence: those files.
- D-13 (Docs and tests): New tests and comments may cite `#23`, `#24` and `#108`, never a requirement id or a decision tag, and hand edits are not followed by `cargo fmt` over the workspace. Evidence: `crates/terminus-core/tests/planning_tags.rs`, `crates/terminus-core/tests/feedback.rs` (a test doc that opens with `#40:`), `.planning/phases/2/CONTEXT.md`.
