# Phase 5: Terminal output escaping - Context

Gathered: 2026-10-19
Feeds: /cad-plan 5

## Scope boundary

In: One shared helper in the `terminus` binary escapes C0 controls other than tab and newline, DEL, and C1 controls as `\u00XX` in every archived string that the human output of `terminus search`, the `terminus show` window and header, and `terminus observations` prints (RCL-12, #63, #65, #66). That covers the regression tests at the process boundary, the docs that describe terminal output, and RCL-12's corrected wording.
Out: The record body `terminus show <id>` prints (D-01). Any change in `terminus-core`, to `--json`, the MCP tools, the hooks or the recall golden (D-02, D-06). Stripping controls at ingest or when an observation is stored (D-03). `sessions`, `usage`, `status`, `export` and `doctor` (D-05). A switch that escapes only when stdout is a terminal, and any new crate (D-10).
Deferred: None.
Plan shape: one plan.

## Durable decisions

- D-01 (show body): The record body `terminus show <id>` prints stays byte for byte, as `docs/commands.md:74` and the `show.rs` module doc promise. Only the window and the header are escaped. ESC and BEL cannot reach the terminal through the body, because the body is the archived JSON line and JSON escapes every C0 control. DEL and C1 can, because JSON does not require escaping them, and `THREAT-MODEL.md` says so. Measured 2026-10-19T13:47Z with `ctrl_census.py` over 2,791 transcripts and 802,765 lines, all of which parsed: 0 raw C0 bytes, 65 raw DEL bytes in 8 files, and 4 raw UTF-8 C1 sequences in 2 files. Escaping DEL and C1 in the body was rejected, because it would end human mode as a way back to the archived bytes and rewrite the fidelity claim. Escaping the body only when stdout is a terminal, as #66 suggests, was rejected for the reason in D-10. RCL-12's row was corrected to say the body stays byte for byte. Evidence: `crates/terminus/src/cmd/show.rs:9-21`, `:113-119`; `crates/terminus-core/src/recall/get.rs:46-63`; `docs/commands.md:74`; `.planning/ROADMAP.md:58`; `.planning/REQUIREMENTS.md:39`.
- D-02 (Where the helper lives): The one shared helper lives in the `terminus` binary crate, beside `out.rs`, and runs where human output is written, after core has redacted, flattened and windowed. Core's excerpt, context text and observation document stay as they are, because `--json`, the MCP tools, the hook output and the recall golden all read those same values. An excerpt that holds a control prints longer than `EXCERPT_CHARS`, because escaping runs after the 240-character cut. Escaping inside core was rejected because it changes `--json`, the MCP `recall_search` and `recall_context` results and the pinned golden. Evidence: `crates/terminus/src/out.rs:1-7`; `crates/terminus/src/cmd/mcp/tools.rs:413`, `:479`; `crates/terminus-core/tests/recall_golden.rs:1-14`; `crates/terminus-core/tests/goldens/recall-projections.txt`; `crates/terminus-core/src/recall/excerpt.rs:93-105`.
- D-03 (No ingest stripping): Nothing is stripped at ingest or in `mechanical::clip`, so the stored observation document keeps its controls and only the human output changes. This rejects the option #63 raises. Stripping at ingest makes the store lossy, which the project's egress-only rule forbids. It would also change `observations --json`, and existing rows would keep their controls until `observations regenerate` ran. Evidence: `crates/terminus-core/src/observe/mechanical.rs:422-431`; `crates/terminus/src/cmd/observations.rs:236-243`; `.planning/phases/2/CONTEXT.md` (D-01); `.planning/PROJECT.md` Key Decisions ("Redact at egress, never at ingest").

## Decisions

- D-04 (What gets escaped): Inside the three commands, every archived string the human output prints goes through the helper. For `search` that is the excerpt and the header's day, transcript file name and project. For `show` it is each window turn's `text`, `record_type` and `tool_name`, the `continues_from` line, and the header's `ts`, file name and project. For `observations` it is every fact list and the header's branch and file name. A stored `ts` is any JSON string the transcript carried, and #66 names the record type, tool name and `continues_from`. Evidence: `crates/terminus/src/cmd/search.rs:139-147`, `:175-181`; `crates/terminus/src/cmd/show.rs:99-111`, `:147-164`; `crates/terminus/src/cmd/observations.rs:258-283`; `crates/terminus-core/src/lineage.rs:5`.
- D-05 (Other commands): `sessions` (project and branch), `usage` (project names), `status` (run notes and errors), `export`, `doctor`, and the scope reasons printed on stderr stay out of this phase. The scope reasons carry user-typed or config paths, not transcript content. A branch name holding a control prints escaped in `observations` and raw in `sessions`. Evidence: `crates/terminus/src/cmd/sessions.rs:96-113`; `crates/terminus/src/cmd/usage.rs:59-66`; `crates/terminus/src/cmd/status.rs:142-153`; `crates/terminus-core/src/recall/scope.rs:94-107`; `.planning/ROADMAP.md:57-64`.
- D-06 (`--json`): `--json` output from all three commands stays byte-identical. The docs must not say `--json` escapes control characters. serde_json 1.0.151 escapes only U+0000 to U+001F, `"` and `\`, so DEL and C1 already pass through `--json` raw. Evidence: `serde_json-1.0.151/src/ser.rs:2147-2165`; `Cargo.lock:360-361`; `crates/terminus/src/cmd/json.rs:107-114`.
- D-07 (`--raw`): `--raw` still only lifts redaction. Escaping applies in human mode with or without it. Giving `--raw` a second job would put escape sequences back on the terminal under a flag documented as a redaction switch. Evidence: `crates/terminus/src/cmd/search.rs:16-23`, `:209-214`; `crates/terminus/src/cmd/show.rs:264-269`; `docs/commands.md:69`, `:78`.
- D-08 (Escape set): The escaped set is U+0000 to U+001F except U+0009 and U+000A, plus U+007F to U+009F, which is exactly `char::is_control` minus tab and newline. A compiled check on 2026-10-19 found `char::is_control` is true for exactly the 65 code points in U+0000 to U+001F and U+007F to U+009F, tab and newline among them, so the escaped set is 63 code points. CR, VT, FF and NEL are in the set. Format characters such as U+202E and U+200B are not. Excerpts and window text already arrive without TAB, LF, VT, FF, CR or NEL, because `flatten` collapses every whitespace run. Observation `commands` are only clipped, so a heredoc command keeps raw LF and can hold CR. Decoded CR appears 5,078 times in 79 of 2,791 transcripts. Leaving CR out would let a stored command overprint its own `observations` line. Evidence: `crates/terminus-core/src/recall/excerpt.rs:236-256`; `crates/terminus-core/src/observe/mechanical.rs:285-298`, `:422-431`; `crates/terminus-core/src/index/entity.rs:361-371`.
- D-09 (Visible form): An escaped character prints as its JSON spelling in lowercase hex: `\u001b`, `\u0007`, `\u007f`, `\u009b`. That is ASCII, it matches what serde_json writes for C0, and it matches what the archived line itself holds, so `show <id> --after N` spells a character the same way in the body and in the window. A 400-file sample on 2026-10-19 held 1,641 `\u001b`, 106 `\u0007` and no uppercase `\u001B`. `str::escape_debug` was rejected because it also escapes tab, newline, quotes, backslash, U+202E and U+200B, and spells ESC `\u{1b}`. `\x1b` was rejected because it misdescribes C1. Caret notation was rejected because it has no form for C1 and collides with a literal `^[`. Control Pictures were rejected because they arrive garbled under a non-UTF-8 locale. Evidence: `crates/terminus-core/src/recall/excerpt.rs:42-47`; `serde_json-1.0.151/src/ser.rs:1786`; `crates/terminus/src/cmd/show.rs:113-119`.
- D-10 (No switch, no crate): The helper uses std alone and adds no crate. It escapes the same way whether stdout is a terminal, a pipe, or the model's context through Bash. A terminal-only rule was rejected because the process-boundary tests capture stdout through a pipe and could never reach the fixed branch. Evidence: `crates/terminus/src/cmd/install/mod.rs:25`, `:476`; `crates/terminus/tests/recall_cli.rs:68`; `THREAT-MODEL.md:127`; `.planning/phases/3/CONTEXT.md` (D-13).
- D-11 (Fixture spelling): The planted ESC and BEL are written in the fixture as the JSON escapes `\u001b` and `\u0007` inside a `tool_result` content or `toolUseResult.stderr` string, the way Claude Code writes them, never as raw bytes. A raw ESC byte is not valid JSON, so that line would be archived with no projection and the test would pass before the fix. The 2026-10-19 census found decoded ESC 26,822 times in 190 of 2,791 transcripts, mostly under `user/message/content` (13,097) and `user/toolUseResult/stdout` (10,931), and BEL 156 times in 7 files. Every one of those subtrees is one `text::project` reads. Evidence: `crates/terminus-core/src/index/text.rs:11-21`; `crates/terminus-core/src/recall/excerpt.rs:222-226`; `crates/terminus/tests/observations.rs:225-240`.
- D-12 (Regression tests): The `search` and `show --before/--after` regression test lives in `crates/terminus/tests/recall_cli.rs`. The `observations` test lives in `crates/terminus/tests/observations.rs` and uses that file's inline transcript builder, because `recall_cli` ingests with `ingest <path>`, which never closes a session, and only a bare `ingest` writes observation rows. A shared fixture for `search` and `show` joins `TRANSCRIPT_FIXTURES` last, as a rooted fixture with its own project key and a row in `tests/fixtures/README.md`, the way phase 2 D-13 added one, so the turn ids the recall golden pins do not move. Each test asserts that human stdout holds no 0x1b or 0x07 byte and does hold the visible escape, and that the `--json` value still decodes to the raw character. Evidence: `crates/terminus/tests/recall_cli.rs:78-92`; `crates/terminus/tests/observations.rs:105-125`; `crates/terminus-core/src/testkit.rs:16-32`, `:60-91`, `:190-192`; `tests/fixtures/README.md`.
- D-13 (Docs): The docs change in the same change as the code. `THREAT-MODEL.md:127`, which names this gap with `[VERIFY]`, is rewritten to describe the escape, the DEL and C1 the `show` body still passes (D-01), and `--json` passing DEL and C1 through (D-06). The `search`, `show` and `observations` sections of `docs/commands.md` describe the escape, and `CHANGELOG.md` gets an `[Unreleased]` entry under `### Fixed`. `SECURITY.md` and `docs/json-shapes.md` stay as they are, because neither describes human output and `--json` does not change. The pull request carries `Fixes #63`, `Fixes #65` and `Fixes #66`; all three are open and labelled `sev: medium` and `security`. Evidence: `THREAT-MODEL.md:127`; `docs/commands.md:57-95`; `CHANGELOG.md:10`, `:35`; `docs/json-shapes.md:30-32`.

## Acceptance criteria

- [ ] AC1: With ESC and BEL archived in a tool result, the human output of `terminus search`, the `terminus show --before/--after` window and `terminus observations` holds no ESC or BEL byte, and shows `\u001b` and `\u0007` where they were. A control planted in a turn's time or tool name prints the same way in the header.
- [ ] AC2: Every code point from U+0000 to U+001F except tab and newline, plus U+007F to U+009F, prints in human output as its lowercase `\u00XX` escape. Tab, newline, U+200B and U+202E print unchanged.
- [ ] AC3: The `--json` output of all three commands on the planted transcript is byte-identical to what it was before the change.
- [ ] AC4: The body `terminus show <id>` prints is byte-identical to what it was before the change. With `--raw`, the window and header are still escaped.
- [ ] AC5: Each regression test fails on the commit before the fix and passes after it.

It describes the escape, the DEL and C1 the `show` body still passes, and `--json` passing DEL and C1 through. `docs/commands.md` describes the escape for all three commands, and `CHANGELOG.md` `[Unreleased]` carries #63, #65 and #66 under `### Fixed`.

## Flagged assumptions

- Which terminals act on UTF-8-encoded C1 controls (U+009B CSI, U+009D OSC), and which honor an OSC 52 clipboard write or an OSC 8 link by default, is not settled; John left it flagged - Unclear; if wrong: the `THREAT-MODEL.md` entry over- or under-states the impact, which it words as depending on the terminal. The fix escapes C1 either way.
- The helper reads `&str` code points, because the excerpt, the window text and the facts are all strings decoded from JSON, so a lone 0x80 to 0x9F byte cannot reach it - Confident, the census found 0 lines that are not JSON; if wrong: a byte-level path is needed for a field that is not valid UTF-8.
- ROADMAP phase 5 success criterion 1 still reads as covering all of `show`. D-01 and the corrected RCL-12 narrow it to the window and the header - Likely to matter at verify; if wrong: a check built from the roadmap line alone expects the body to be escaped and fails the phase against D-01.
- Whether `search` and `show` get a shared rooted fixture or an inline temp transcript is the planner's call - Likely either satisfies AC1 and AC5; if wrong: a fixture inserted anywhere but last moves the golden's turn ids.
