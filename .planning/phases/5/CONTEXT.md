# Phase 5: One ingest pass - Context

Gathered: 2026-10-23
Feeds: /cad-plan 5

## Scope boundary

In: One pass driver in terminus-core that runs the tree pass, the backfill and single-file ingest, with one per-file failure handler and one end-of-pass `runs` insert; `RunRow`, `record_run` and both `record_pass` copies removed (#31). Single-file ingest writes a `runs` row on every run that holds the lock, its recovery lines in `notes`. Recovery's lines and observe's "waiting to be observed" line written to `notes` instead of `error`, so a pass that failed nothing shows no error in `status` or `doctor` (#96). One core reader for the last run, used by `status` and `doctor` (#31). The docs and doc comments that state the old split rewritten.
Out: Giving the backfill or single-file ingest the tree pass's post-walk steps. Any change to the public signatures of `pass::run_with`, `backfill::run_with` and `ingest::run_with`. A `note` state in `doctor`'s `last_run` check. Changing `reading_the_hooks_stdout_to_eof_returns_at_once_while_the_ingest_still_runs`. Running `cargo fmt` over the workspace. The other open issues.
Deferred: None.
Plan shape: multiple plans, same phase (an estimated nine to eleven tasks across the driver, single-file ingest through it, the recovery and observe split, the one reader, the process-level tests and the docs, against `workflow.max_plan_tasks` 8).

## Durable decisions

- D-01 (Single-file ingest): Single-file ingest's `runs` row moves out of the file's own transaction into the driver's end-of-pass insert, the way the tree pass already writes its row. A kill between the file's commit and the row leaves a committed file with no row. Rejected: a driver callback that writes the row inside the last file's transaction, which is `RunRow` under another name and a second path. Evidence: `crates/terminus-core/src/ingest/mod.rs` (`RunRow` at 226, `record_run` at 1625, `ingest_locked`, `apply`), `crates/terminus-core/src/ingest/pass.rs` and `crates/terminus-core/src/ingest/backfill.rs` (the dummy `Instant::now()` passed to `ingest_locked`), `crates/terminus/tests/crash.rs` and `crates/terminus/tests/backfill.rs` (both leave `runs` out of the convergence comparison), the `RunRow::PassOwns` unit test in `ingest/mod.rs`.

## Decisions

- D-02 (Driver): One driver in core runs every pass in one order: take the lock, recover, read the rows, run the walk, handle each file's failure, then insert one `runs` row. Each caller hands it its own walk: the sequential walk, the backfill's threaded pipeline, or one named file. Evidence: `crates/terminus-core/src/ingest/pass.rs` (`locked`), `crates/terminus-core/src/ingest/backfill.rs` (`run_with`), `crates/terminus-core/src/ingest/mod.rs` (`run_with`), the 2026-10-22 comment on #31 ("One pass driver that takes the walk, with single-file ingest as a list of one").
- D-03 (Driver): `pass::run_with`, `backfill::run_with` and `ingest::run_with` stay as thin entry points with their current signatures and return types (`PassOutcome`, `Report`, `Outcome`), so about 140 test call sites across `crates/terminus-core/tests`, `crates/terminus/src/cmd/ingest.rs` and `crates/terminus/src/cmd/backfill.rs` do not change. Evidence: those call sites.
- D-04 (Driver): Each caller keeps the steps it runs today. Only the tree pass drains decisions, labels, observes, applies retention and checks whether a snapshot is due; the backfill and single-file ingest run none of these. Evidence: `docs/design/0003-ingest.md:92,99`, `crates/terminus-core/tests/backfill.rs` (`POST_WALK_TABLES`), `crates/terminus-core/src/ingest/pass.rs` (the post-walk steps in `locked`).
- D-05 (Driver): The `runs` row stays a single INSERT at the end of the pass, after the walk and after the tree pass's post-walk steps, never a row inserted at the start and updated at the end. That keeps the `after-blob` fault point ahead of every `runs` write, so the hook stdout test from #75 stands unchanged. Evidence: `crates/terminus/tests/hook.rs` (`runs_at_eof`), `crates/terminus-core/src/ingest/mod.rs` (`fault::stall(fault::AFTER_BLOB)` in `prepare`), `crates/terminus/src/cmd/hook.rs` (`spawn::detached(&["ingest"])`), `.planning/phases/3/UAT.md`.
- D-06 (Driver): The sequential walk and the backfill's writer share one per-file failure handler: record the path and reason, and set the divergence flag on `TranscriptDiverged` or `TranscriptRewritten`. The per-file result the driver matches has no `LockHeld` or `Excluded` arm; those stay only on single-file ingest's public `Outcome`. Evidence: the duplicated arms in `crates/terminus-core/src/ingest/pass.rs` and `crates/terminus-core/src/ingest/backfill.rs`, the `Excluded` doc in `crates/terminus-core/src/ingest/mod.rs` ("Only [`run`] produces this"), the 2026-10-22 comment on #31.
- D-07 (Single-file ingest): Single-file ingest writes one `runs` row on every run that holds the lock: committed is files seen 1, committed 1, failed 0; up to date is 1, 0, 0; failed is 1, 0, 1 with the reason in `error`. Its recovery lines, discarded today as `_recovered`, go into that row's `notes`. Its exclusion check stays before the lock, and it still reads only its own key's row. After a named file fails, `doctor` reports a problem until the next tree pass. John chose this over a row on commit and failure only, and over a row on commit only as today. Evidence: `crates/terminus-core/src/ingest/mod.rs` (`run_with`, the `UpToDate` doc "not even to `runs`"), `crates/terminus-core/src/ingest/pass.rs` ("One row, whatever happened"), `crates/terminus/tests/status.rs` (the committed-row test), `crates/terminus/tests/lock_race.rs` (a contended run writes nothing).
- D-08 (Single-file ingest): A named file's failure still comes back to the caller as the typed `Error`, so `terminus ingest <path>` still exits non-zero on a damaged file, and a named file still never sets the divergence flag. The driver writes the failure into the row, then returns the error, as the tree pass already does for a fatal walk error. Evidence: `crates/terminus-core/tests/pass.rs` (`matches!(err, Error::TranscriptDiverged { .. })`, "Only the walk flags a divergence"), `crates/terminus-core/tests/ingest.rs`, `crates/terminus-core/src/ingest/pass.rs` ("a caller that named one file deserves the error it asked about"), `crates/terminus/src/cmd/ingest.rs` (every `Ok` maps to success).
- D-09 (Status and doctor): The fix goes in the writer. `Recovered::lines()` moves from the `error` list to the `notes` list, so a pass that only recovered leaves `runs.error` null. `status` prints `error` only when the column is non-null and `doctor`'s `(None, 0) => Ok` already passes such a run, so neither command's logic changes. Since #105, recovery's only lines are lowered or removed watermarks. Evidence: `crates/terminus-core/src/ingest/pass.rs` (`record_pass`: `errors.extend(summary.recovery.lines())`), `crates/terminus-core/src/ingest/backfill.rs` (its `record_pass`), `crates/terminus-core/src/recover.rs`, `crates/terminus/src/cmd/status.rs`, `crates/terminus/src/cmd/doctor.rs` (`last_run`).
- D-10 (Status and doctor): Observe's "N more finalized session(s) are waiting to be observed" line moves to `notes` too. Observation results are split into errors and notes the way labels and retention already are, and a session whose observation could not be written stays an error. Unreadable directories, discarded decision files, failures in labelling, observation and retention, and `pass failed:` all stay under `error`. John chose this over filing the line as its own issue, because #96 says "A note from a pass that failed nothing is not reported as an error by `status` or `doctor`." Evidence: `crates/terminus-core/src/observe/mod.rs` (the `over > 0` line, `MAX_PER_PASS` = 100), `crates/terminus-core/src/ingest/pass.rs` (`errors.extend(summary.observations.lines())`), `crates/terminus-core/src/retention/apply.rs` (retention's matching line is a note), `crates/terminus-core/tests/feedback.rs` (discarded decision files under `error`), #96.
- D-11 (Status and doctor): `doctor` reports a last run that only recovered as `ok`, not as a new `note` state, and exits 0. Evidence: `crates/terminus/src/cmd/doctor.rs` (`last_run` does not select `notes`), `crates/terminus/tests/doctor.rs` (a run with only notes is `ok`), `docs/commands.md` (`doctor` exits 1 only on `problem`).
- D-12 (Status and doctor): `status` and `doctor` read the last run through one reader in core, replacing the two `SELECT ... FROM runs ORDER BY id DESC LIMIT 1` queries that read the row into different structs. The binary crate still never names rusqlite. John chose this so #31 closes with its whole fix. Evidence: `crates/terminus/src/cmd/status.rs:62`, `crates/terminus/src/cmd/doctor.rs:862`, #31's fix line ("one reader for the last run") and its 2026-10-19 comment.
- D-13 (Proof): Criteria AC4 and AC5 are proved end to end: a real store gets a watermark pushed past its archive, or a shrunk transcript, and then `terminus ingest`, `status` and `doctor` run as processes. A `notes` or `error` value planted with UPDATE proves only how a row is displayed and does not count. A recovery-only pass on a copy of John's live store stays a check run on his machine. Evidence: `crates/terminus-core/tests/recover.rs` (`damage()`), `crates/terminus/tests/status.rs` (the shrunk-transcript test, and the planted rows), `crates/terminus/tests/doctor.rs`, `.planning/phases/1/UAT.md` (the live-store copy run).
- D-14 (Docs): The docs and doc comments that state the old split change with the code: `docs/commands.md:122` ("print under `error` even when nothing failed"), `docs/json-shapes.md:242-245` ("a watermark repaired" under `error`), `docs/design/0003-ingest.md:92` (a single-file row written in the file's transaction, only when there are new bytes), the `UpToDate` doc in `crates/terminus-core/src/ingest/mod.rs`, and `record_pass`'s doc in `crates/terminus-core/src/ingest/pass.rs`. Every comment naming `record_pass` or `record_run` is rewritten, including in `crates/terminus-core/src/reindex.rs`, `crates/terminus-core/src/feedback/mod.rs`, `crates/terminus-core/src/observe/mod.rs` and `crates/terminus-core/tests/pass.rs`. Comments are rewrapped by hand, `cargo fmt` is not run over the workspace, and new comments and tests may cite `#31` and `#96` but never a requirement id or a decision tag. Evidence: those files, `crates/terminus-core/tests/planning_tags.rs`.

## Acceptance criteria

- [ ] AC1: `git grep -nE '\bRunRow\b|fn record_run|fn record_pass' crates/` prints nothing, and `pass::run_with`, `backfill::run_with` and `ingest::run_with` each call the same one driver function in core. `git grep -n 'FROM runs ORDER BY id DESC' crates/terminus/src` prints nothing, because `status` and `doctor` read the last run through one core function
- [ ] AC2: A tree pass and `terminus backfill`, each run on its own copy of one store with the same damaged watermark, leave last `runs` rows with the same set of non-null columns, and both rows' `notes` hold recovery's line
- [ ] AC3: `terminus ingest <path>` writes one `runs` row when the file commits, when it is already up to date, and when it fails; in the failure case it exits non-zero and the row's `error` names the file
- [ ] AC4: On a real store whose watermark recovery must lower, with no failing file, after `terminus ingest`, `terminus status` prints no `error` line and shows recovery's line under notes, `terminus status --json` has `error: null`, and `terminus doctor` exits 0
- [ ] AC5: On a store with one shrunk transcript, after `terminus ingest`, `terminus status` prints that file under `error` and `terminus doctor` exits 1
- [ ] AC6: A pass that finds more than 100 newly finished sessions and fails nothing records the "waiting to be observed" line in `notes`, not `error`, and `terminus doctor` exits 0
- [ ] AC7: `cargo test --workspace --all-features` passes, and the phase's diff leaves `reading_the_hooks_stdout_to_eof_returns_at_once_while_the_ingest_still_runs` unchanged
