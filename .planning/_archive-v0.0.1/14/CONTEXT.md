## Durable decisions

- D-01 (era): A request is modern when `params._meta` carries `io.modelcontextprotocol/protocolVersion`. A request without it is served as legacy, exactly as today, with no check that an `initialize` came first; `initialize` itself selects legacy. Refusing a `_meta`-less request with `-32602` was rejected: it would break any client or test that sends `tools/list` before `initialize`, and the spec notes legacy servers never checked ordering. Evidence: spec 2026-07-28 `basic/index` (per-request protocol fields), `basic/versioning` ("a dual-era server selects its behavior from how the client opens"), `crates/terminus/src/cmd/mcp/mod.rs:151-179`, `crates/terminus/tests/mcp.rs:399-423`.
- D-02 (result fields): Every result the server sends carries `resultType` `"complete"` and `_meta.io.modelcontextprotocol/serverInfo` (`name` `terminus`, `version` the crate's), on both eras: `initialize`, `ping`, `tools/list`, `tools/call` and `server/discover`. `tools/list` always carries `ttlMs` and `cacheScope`. Sending them only on modern requests was rejected: the spec made the fields additive (clients MUST treat an absent `resultType` as complete, and a JSON-RPC result may carry any members), and one shape keeps the server a pure function of one line. If a Claude Code older than 2.1.287 rejects them, this is the decision to revisit. Evidence: spec `basic/index` (Result Responses), `crates/terminus/src/cmd/mcp/rpc.rs:147-149`, `crates/terminus/src/cmd/mcp/tools.rs:279-294`.

## Decisions

- D-03 (era): `2026-07-28` is the only modern revision. The server reads `io.modelcontextprotocol/protocolVersion` from `_meta` and nothing else; `clientCapabilities` and `clientInfo` are not checked, because the three tools rely on no client capability. Evidence: spec `basic/index` ("a server MUST NOT rely on capabilities the client has not declared").
- D-04 (discover): `server/discover` answers `{"resultType":"complete","supportedVersions":["2026-07-28"],"capabilities":{"tools":{}},"_meta":{"io.modelcontextprotocol/serverInfo":{"name":"terminus","version":<crate>}},"ttlMs":0,"cacheScope":"private"}`. No `instructions`: anything there sits in every session's context, and the tool descriptions already say what each tool returns. It is answered whether or not the request carries `_meta`. Evidence: spec `server/discover`, `.planning/PROJECT.md` Key Decisions (three tools, one-line descriptions), `crates/terminus/src/cmd/mcp/mod.rs:189-197`.
- D-05 (discover): `supportedVersions` lists `2026-07-28` alone, not the legacy revisions, because a client picks one of them for stateless requests and no legacy revision has a stateless form. Evidence: spec `server/discover` ("the client should choose one of these for subsequent requests").
- D-06 (cache fields): `ttlMs` is `0` and `cacheScope` is `"private"`, matching Baley. Zero so a host fetches the list again rather than keep one from an older binary; private because the list comes from one user's own server. The spec calls `public` appropriate for a list identical for all users, which this one is, but on stdio no shared cache exists and the two are indistinguishable. Evidence: `/code/baley/crates/baley/src/mcp/tools.rs:72-80`, Baley issue #174, spec `server/utilities/caching`.
- D-07 (version mismatch): A modern request naming any version other than `2026-07-28`, `server/discover` included, is refused with `-32022` and `data` `{"supported":["2026-07-28"],"requested":<asked>}`. It is the one new error code this server emits; `-32020` and `-32021` are never sent. Evidence: spec `basic/versioning` (Protocol Version Negotiation), `basic/transports/stdio` (Backward Compatibility), `crates/terminus/src/cmd/mcp/rpc.rs:31-49`.
- D-08 (initialize): `initialize` is unchanged. `PROTOCOL_VERSIONS` keeps `2025-11-25`, `2025-06-18`, `2024-11-05` and `2024-10-07`; `2026-07-28`, like any unknown revision, is answered `2025-06-18`. The server offers 2026-07-28 through `server/discover`, because the revision has no `initialize`. The roadmap's third success criterion says otherwise and is corrected with `/cad-phase edit 14`, not in this phase. Evidence: `crates/terminus/src/cmd/mcp/mod.rs:58-83,183-198`, `.planning/phases/12/CONTEXT.md` D-02, spec `basic/versioning` (Terminology, Compatibility Matrix).
- D-09 (unchanged): `ping` is still answered. Notifications still get no answer. `tools/call` keeps `-32602` for an unnamed or unknown tool and its `isError` split. Unknown methods still get `-32601`. The process still ends at EOF. Evidence: `crates/terminus/src/cmd/mcp/mod.rs:168-176`, `crates/terminus/src/cmd/mcp/rpc.rs:106-109`, `crates/terminus/src/cmd/mcp/tools.rs:256-277`, spec `basic/transports/stdio` (Shutdown).
- D-10 (docs and closing): `docs/design/0006-recall-through-mcp.md` changes in the same PR: the `initialize` section, a `server/discover` section, the result shapes including the line saying `ping` gets `{}`, the `-32022` refusal, and figure 1. `CHANGELOG.md` `[Unreleased]` gets an Added entry. The `PROTOCOL_VERSIONS` doc comment at `crates/terminus/src/cmd/mcp/mod.rs:65-69` stops saying MCP 2 is left out. The PR body carries `Fixes #45`. Evidence: `.planning/REQUIREMENTS.md` DOC-04, `.planning/phases/12/CONTEXT.md` D-15, `docs/design/0006-recall-through-mcp.md:86-96,226-252`.

## Flagged assumptions

- Claude Code's validator for results negotiated through `initialize` strips unknown members rather than rejecting them, so D-02's fields are harmless to a legacy client - Likely; if wrong: a Claude Code older than 2.1.287 loses the tools, and D-02 is revisited to send the fields only on modern requests.
- Claude Code requires nothing on a `DiscoverResult` beyond what the spec lists, and in particular does not need `instructions` - Likely; if wrong: AC6's debug log shows the rejection and the missing field is added.
