# Phase 11: How Terminus Works - Plan 3 of 3

## Goal

An engineer who wants to see inside Terminus can open `docs/design/`, read an overview that starts with one diagram of the whole system from the hook to ingest to the archive to search to recall, and follow a link to one doc per part, each describing the system as it stands now, with Mermaid diagrams GitHub renders with no other tool. This plan writes the last three part docs, recall through the MCP server, injection, and install and release, and points `README.md` at the finished folder.

- Each has at least one captioned Mermaid diagram of an allowed type with no theme, `style`, `classDef` or fill, and the values each names match the code (D-13, D-15, D-16).
- The recall doc says what each of `recall_search`, `recall_context` and `recall_get` returns, naming every field its result carries.
