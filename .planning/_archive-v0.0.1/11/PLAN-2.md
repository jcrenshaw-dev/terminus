# Phase 11: How Terminus Works - Plan 2 of 3

## Goal

An engineer who wants to see inside Terminus can open `docs/design/`, read an overview that starts with one diagram of the whole system from the hook to ingest to the archive to search to recall, and follow a link to one doc per part, each describing the system as it stands now, with Mermaid diagrams GitHub renders with no other tool. This plan writes the first four part docs, the write path and the read path: hooks, ingest, the archive and its block rows, and search.

## Must be true when done

- `docs/design/` holds `0002-hooks.md`, `0003-ingest.md`, `0004-archive-and-block-rows.md` and `0005-search.md`, and the `## ` headings of each equal `TEMPLATE.md`'s, in the same order.
- Each of the four has at least one Mermaid diagram with a `*Figure N.` caption under it, every diagram is a `flowchart`, `sequenceDiagram`, `stateDiagram-v2` or `erDiagram`, and none sets a theme, `style`, `classDef` or fill.
- The values each doc names match the code: the hook's events, limits and deadlines (D-09), the ingest pass's steps in their order (D-10), every table and its columns, the block constants and the store versions (D-11), and the search limits and ranking (D-12).
- The links from the overview and the index to these four docs resolve, each doc names its modules by full repo-relative path linked from the doc, and no doc cites code by line number.
- `/cad-docs-verify` reports no stale claim in any of the four.
- The owner has reviewed each of the four in RustRover, and each doc's diagrams render on GitHub in light and dark theme (human-verify).
